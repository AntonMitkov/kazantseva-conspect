## 1.6.4 Организация кода через пространства имён

<!-- TODO: начало параграфа (Пример 1.86: файлы geometry.hpp и geometry.cpp) на фото не попало; видно только окончание geometry.cpp: определение geometry::perimeter, `return 2 * (width + length);` -->

Файл `main.cpp`:

```cpp
#include <iostream>

#include "geometry.hpp"

int main()
{
    constexpr double ROOM_WIDTH = 3.0;
    constexpr double ROOM_LENGTH = 4.5;
    std::cout << geometry::area(ROOM_WIDTH, ROOM_LENGTH) << ' '

Результат работы программы:

```

```

Тот же код в виде модуля C++20 — файл `geometry.cppm`; в `main.cpp` директива `#include "geometry.hpp"` заменяется объявлением `import geometry;`, остальное не меняется:

```cpp
export module geometry;

export namespace geometry {
double area(double width, double length)
{
    return width * length;
}

double perimeter(double width, double length)
{
    return 2 * (width + length);
}
} // namespace geometry
```

Функцию, объявленную в пространстве имён, в файле реализации определяют одним из двух способов:

1. внутри повторно открытого блока `namespace geometry { … }` — как `area`;
2. по квалифицированному имени `geometry::perimeter` вне блока.

Разница видна при опечатке. Если в первом способе написать `aera` вместо `area`, компилятор ошибки не заметит: он объявит в пространстве имён ещё одну функцию `aera`, а определения `geometry::area` не будет — и ошибку сообщит только компоновщик (в Linux — `undefined reference to …`, в macOS — `Undefined symbols …` с именем `geometry::area(double, double)`). Во втором способе опечатка `geometry::perimetr` — ошибка компиляции: определение по квалифицированному имени должно соответствовать уже объявленной функции (`out-of-line definition of 'perimetr' does not match any declaration in namespace 'geometry'`).

В заголовочном файле имена из других пространств имён пишут полностью — `std::string`, а не `string` после `using namespace std;` (см. [[lekciya-16#1.6.3 Ключевое слово using|1.6.3 Ключевое слово using]]).

### Вложенные пространства имён

Пространства имён можно вкладывать друг в друга — так крупную библиотеку делят на части; в стандартной библиотеке это, например, `std::chrono` и `std::filesystem`. Неквалифицированное имя во вложенном пространстве имён ищется по общему правилу из [[lekciya-16#1.6.1 Область видимости|1.6.1 Область видимости]]: сначала в нём самом, затем во внешних пространствах имён — вплоть до глобального — и только среди объявлений выше точки использования. Снаружи к вложенному пространству имён обращаются по полному пути: `outer::inner::x`.

### Соглашения об организации кода

- Всё, что предоставляет проект или библиотека, помещают в одно пространство имён верхнего уровня с именем проекта — например, `calculator` для учебного проекта (см. 2.2.2.2 «Этапы разработки алгоритмов»).
- Имена пространств имён записывают строчными буквами (п. 4l стиля курса).
- Вкладывать пространства имён глубже двух-трёх уровней без необходимости не стоит: полные имена становятся длинными.
- Функция `main` остаётся в глобальном пространстве имён: функция `main`, объявленная внутри пространства имён, — обычная функция, а не точка входа программы.
- Вспомогательные функции, которые не должны быть видны в других файлах, помещают в безымянное пространство имён — тема 3.5 (см. ниже).

## 3.5 доп. Безымянные (анонимные) пространства имён

Фрагмент заметки «3.5 доп. ADL и анонимные пространства имён» (раздел 3).

### Ещё один механизм — анонимные пространства имён

> [!abstract] Безымянное (анонимное) пространство имён (unnamed namespace)
> пространство имён без указанного имени — `namespace { ... }`. Все объявленные в нём сущности видимы только в пределах текущего файла (единицы трансляции). Современная замена ключевому слову `static` для ограничения видимости имени одним файлом (internal linkage).

```cpp
namespace {
    int counter = 0;   // виден только в этом .cpp файле,
                       // не конфликтует с counter в других файлах проекта
}
```

**Зачем это нужно.** Компоновщик собирает объектные файлы всех `.cpp` в одну программу. Если в двух файлах определена функция с одним и тем же именем и параметрами, например вспомогательная `int sumDigits(int)`, нарушается правило одного определения (ODR), и компоновка завершается ошибкой повторного определения: `duplicate symbol` в macOS, `multiple definition of` в Linux, `LNK2005` в MSVC. Такое легко получить, когда файл с решением собирается вместе с другими файлами, например с файлами тестов. Безымянное пространство имён делает имя «личным» для файла: в каждом файле своя функция, и конфликта нет.

```cpp
// digits.cpp
#include "digits.hpp"

namespace {

int sumDigits(int number)   // вспомогательная функция: видна только в digits.cpp
{
    // ...
}

} // namespace
```

Именованное пространство имён (`namespace helpers { ... }`) этой задачи не решает: оно общее для всей программы, и функция `helpers::sumDigits`, определённая в двух файлах, снова приведёт к ошибке компоновки.

**Константы.** Константы `const` и `constexpr`, объявленные на уровне файла (вне функций и классов, без `extern` и `inline`), и так имеют внутреннее связывание. Помещать их в безымянное пространство имён не обязательно, но полезно: правило становится единым — всё, что не объявлено в заголовочном файле, находится в безымянном пространстве имён, — и вспомогательная функция, добавленная рядом <!-- TODO: продолжение на фото обрезано -->

### 3.4.1 Перегрузка функций

Часто бывает удобно, чтобы функции, реализующие один и тот же алгоритм для различных типов данных, имели одно и то же имя.

Если это имя мнемонично, то есть несёт нужную информацию, это делает программу более понятной, поскольку для каждого действия требуется помнить только одно имя.

> [!abstract] Перегрузка функций (function overloading)
> использование нескольких функций с одним и тем же именем, но с различными типами параметров и/или различным количеством параметров.

> [!abstract] Разрешение перегрузки (overload resolution)
> процесс, в котором компилятор определяет, какую именно функцию требуется вызвать, по типу фактических параметров.

Английское *resolution* здесь употребляется в смысле «уточнение». Адрес перегруженной функции определяется особым образом (см. ссылки в блоке документации).

> [!important] Тип возвращаемого значения в разрешении перегрузки не участвует
> Механизм разрешения основан на достаточно сложном наборе правил, смысл которых сводится к тому, чтобы использовать функцию с наиболее подходящими аргументами и выдать сообщение, если такой не найдётся.

```cpp
int findMax(int, int);
int findMax(int, int, int);
int findMax(const std::vector<int>&);
int findMax(const std::vector<std::vector<int>>&);
double findMax(const std::vector<Segment>&);  // наибольшая длина отрезка
```

Общий вид перегруженных функций:

```cpp
returnType1 function(parameters_list_1) {
    // statements
}
returnType2 function(parameters_list_2) {
    // statements
}
// ...
```

#### Правила описания перегруженных функций

1. Перегруженные функции должны находиться в одной области видимости, иначе произойдёт сокрытие аналогично одинаковым именам переменных во вложенных блоках.
2. Имена параметров при сравнении объявлений во внимание не принимаются.
3. Перегруженные функции могут иметь параметры по умолчанию, но если после подстановки значений по умолчанию вызову подходят несколько перегрузок одинаково хорошо, вызов неоднозначен (пример 3.11). В различных вариантах перегруженных функций может быть различное количество параметров по умолчанию.
4. Функции не могут быть перегружены, если описание их параметров отличается только:
   - модификатором `const`, например, `int` и `const int`, или
   - значением по умолчанию.

   Функции `f(int)` и `f(int&)` перегрузить можно, но вызов `f(x)` с переменной `x` неоднозначен, поэтому такая пара на практике бесполезна.
5. Спецификатор `const` или `volatile`, применяемый к параметру указательного или ссылочного типа, при сравнении объявлений учитывается.

> [!tip] Перегрузки одного имени выполняют одно действие
> Компилятор не проверяет смысл перегруженных функций, но все перегрузки одного имени должны выполнять одно и то же действие. Если `findMax` для чисел ищет максимум, то и для отрезков она должна искать максимум, а не, скажем, сортировать их (C++ Core Guidelines [7], правила C.162, C.163).

> [!example] Пример 3.11 — Неоднозначный вызов: перегрузка и параметр по умолчанию
> ```cpp
> // разные сигнатуры, но вызов log("Hello") неоднозначен
> void log(std::string msg, int level = 1) {
>     std::cout << "уровень: " << level << '\n';
> }
> void log(std::string msg) {
>     std::cout << "без уровня\n";
> }
> ```
> Ошибка компиляции: при вызове `log("Hello")` компилятор не может выбрать между двумя функциями, потому что обе подходят — одна с параметром по умолчанию, другая без него. Это приводит к неоднозначности <!-- TODO: продолжение на фото обрезано -->

#### Правила выбора перегруженной функции

Разрешение перегрузки компилятор выполняет в три шага:

1. **Кандидаты.** Собираются все функции с вызываемым именем, видимые в точке вызова.
2. **Подходящие функции** (viable functions). Из кандидатов остаются те, которые можно вызвать с данным числом аргументов (с учётом параметров по умолчанию) и для каждого аргумента которых существует неявное преобразование к типу параметра.
3. **Лучшая функция.** Для каждого аргумента определяется ранг преобразования, которое нужно, чтобы передать его в параметр. Выбирается функция, у которой преобразование ни одного аргумента не хуже, чем у остальных подходящих функций, а хотя бы одного — лучше. Если такой функции нет, вызов неоднозначен (ambiguous) и компилятор сообщает об ошибке.

Ранги преобразований — от лучшего к худшему:

1. **Точное совпадение:** тип аргумента совпадает с типом параметра или отличается тривиально — массив преобразуется в указатель, функция в указатель на функцию, к указываемому типу добавляется `const` (`int*` → `const int*`).
2. **Продвижение** (promotion): целочисленное продвижение `bool`, `char`, `short` в `int` и продвижение `float` в `double`.
3. **Преобразование** (conversion): остальные стандартные преобразования — `int` → `double`, `double` → `int`, `long` → `int`, указатель → `bool` и т. п. Все преобразования этого ранга равноценны.
4. **Пользовательское преобразование:** через конструктор или оператор преобразования класса (см. тему 5.2).
5. **Многоточие:** аргумент передаётся в параметр `...` (см. раздел «Многоточие» ниже).

#### Многоточие: функции с переменным числом аргументов

Последним параметром функции может быть многоточие `...`. Такая функция принимает, кроме обязательных параметров, любое число дополнительных аргументов любых типов. Механизм унаследован от языка C; самая известная функция с многоточием — `printf` из `<cstdio>`: `printf("%d + %d = %d\n", a, b, a + b)`.

> [!abstract] Многоточие (эллипсис, ellipsis)
> лексема `...` из трёх точек <!-- TODO: продолжение определения на фото обрезано -->

> [!abstract] Вариативная функция, функция с переменным числом аргументов (variadic function)
> функция, последний параметр которой — многоточие `...`; при вызове ей можно передать после обязательных аргументов произвольное число дополнительных аргументов.

Внутри функции у дополнительных аргументов нет имён, и их читают по одному макросами из заголовочного файла `<cstdarg>`:

- `std::va_list args;` — объявить переменную для обхода аргументов;
- `va_start(args, последний_параметр);` — начать обход после последнего именованного параметра;
- `va_arg(args, тип)` — прочитать следующий аргумент, считая, что он имеет указанный тип;
- `va_end(args);` — завершить обход.

Сколько аргументов передано и какого они типа, функция сама узнать не может — об этом договариваются заранее. Обычно число аргументов передают отдельным параметром (как в примере ниже), описывают их строкой формата (как у `printf`) или завершают список особым значением — сторожевым (sentinel).

> [!example] Пример 3.15 — Сумма произвольного числа целых
> ```cpp
> #include <cstdarg>
> #include <iostream>
>
> int sum(int count, ...)
> {
>     std::va_list args;
>     va_start(args, count);
>     int total = 0;
>     for (int i = 0; i < count; ++i) {
>         total += va_arg(args, int);
>     }
>     va_end(args);
>     return total;
> }
>
> int main()
> {
>     std::cout << sum(3, 10, 20, 30) << '\n';
>     std::cout << sum(2, 'A', true) << '\n';
>
>     std::cout << sum(0) << '\n';
>     return 0;
> }
> ```

Аргументы, передаваемые в многоточие, проходят **продвижение аргументов по умолчанию** (default argument promotions): `bool`, `char` и `short` превращаются в `int`, `float` — в `double`. Поэтому `va_arg(args, char)` и `va_arg(args, float)` не используют: читать нужно `int` и `double`.

> [!danger] Многоточие отключает проверку типов
> Компилятор не сверяет дополнительные аргументы ни с чем: `sum(2, 1.5, 2.5)` и `sum(3, 1, 2)` компилируются без ошибок и предупреждений. В первом вызове `va_arg` читает `double` как `int`, во втором — читает аргумент, которого нет. Оба случая — неопределённое поведение (см. 2.2.3.4 «Неопределённое поведение (UB)»): программа выводит «мусор» или завершается аварийно. Объекты классов с нетривиальным копированием, например `std::string`, через многоточие передавать нельзя: стандарт оставляет такую передачу на усмотрение реализации, а clang++ отказывается её компилировать (`cannot pass object of non-trivial type …`).

В разрешении перегрузки передача аргумента в многоточие — худший ранг: функцию с `...` компилятор выберет, только если никакая другая перегрузка не подходит. Поэтому функцию с многоточием иногда используют как «запасной вариант» на любые аргументы.

> [!example] Пример 3.16 — Многоточие проигрывает любой другой перегрузке
> ```cpp
> #include <iostream>
>
> void check(int)
> {
>     std::cout << "int\n";
> }
>
> void check(...)
> {
>     std::cout << "что-то другое\n";
> }
>
> int main()
> {
>     check(5);      // точное совпадение → check(int)
>     check('A');    // продвижение char → int лучше многоточия
>     check("text"); // const char* в int не преобразуется → check(...)
>     return 0;
> }
> ```

##### Как функция узнаёт конец списка аргументов

Язык не требует передавать количество аргументов: параметр `count` в примере 3.15 — лишь один из способов договориться. Функция должна как-то узнать, где остановить чтение и какого типа каждый аргумент, потому что сама определить это не может. Распространены три способа:

- **Счётчик** — как `sum(3, 10, 20, 30)` в примере 3.15.
- **Строка формата** — как у `printf`: число и типы аргументов задают спецификаторы `%d`, `%s` и другие.
- **Сторожевое значение (sentinel)** — особое значение, которое передают последним как признак конца списка.

> [!example] Пример — Сумма чисел до сторожевого значения
> ```cpp
> #include <cstdarg>
> #include <iostream>
>
> int sumUntilZero(int first, ...)
> // TODO: тело функции и main на фото не попали
> ```

Счётчик не обязан совпадать с реальным числом аргументов. Если передать больше, чем функция прочитает, ошибки нет: `sum(2, 1, 2, 3)` вернёт 3, а лишний аргумент будет проигнорирован. Неопределённое поведение возникает только в обратном случае, когда прочитано больше, чем передано, как в `sum(3, 1, 2)`.

Именованный параметр тоже не обязателен: объявление `void check(...)` допустимо (см. пример 3.16). До C++26 аргументы такой функции нельзя прочитать, потому что `va_start` требует имя последнего параметра, поэтому такая форма полезна только как «запасной вариант» в перегрузке. C++26 вслед за C23 разрешает вызов `va_start(args)` с одним аргументом, но поддерживают его ещё не все компиляторы.

> [!warning] Ловушка: многоточие без запятой
> Запись `int sum(int count...)` без запятой равносильна `int sum(int count, ...)`, но в C++26 объявлена устаревшей. Перед многоточием всегда ставьте запятую.

### 3.4.2 Шаблоны функций

> [!quote] Документация и стандарт по теме

> - Стандарт, шаблоны функций: https://eel.is/c++draft/temp.fct

#### Зачем нужны шаблоны

Функции, реализующие один и тот же алгоритм для различных типов данных, можно описать с помощью перегрузки (см. 3.4.1):

```cpp
char findMax(char a, char b)
{
    return (a >= b ? a : b);
}
// TODO: остальные перегрузки на фото не попали
```

Выглядит громоздко. И нарушается принцип DRY (см. 7.1.3.3 «DRY и WET»): логика, совпадающая с точностью до типа, копируется в каждой из перегрузок заново.

В языке C++ подобные алгоритмы могут быть описаны с помощью шаблонов функций (Страуструп, стр. 744).

> [!abstract] Шаблон функции (function template)
> обобщённое описание функции, в котором типы данных, которыми оперирует функция, являются параметрами; шаблон функции определяет семейство функций.

Параметры шаблона перечисляются перед описанием функции: `template<typename T, typename S>`.

> [!important] Шаблоны решают эту проблему
> Алгоритм записывается один раз, а функцию для нужного типа компилятор создаёт сам:
> ```cpp
> template<typename T> T findMax(T a, T b)
> {
>     return (a >= b ? a : b);
> }
> ```

> [!example] Пример 3.17 — Шаблон функции `swap`
> ```cpp
> #include <iostream>
>
> template<typename T> void swap(T& a, T& b)
> {
>     T tmp = a;
>     a = b;
>     b = tmp;
> }
>
> int main()
> {
>     int x = 3;
>     int y = 5;
>     swap<int>(x, y);
>     std::cout << "x = " << x << ", y = " << y << '\n';
>
>     double xx = 3.3;
>     double yy = 5.5;
>     swap<double>(xx, yy);
>     std::cout << "xx = " << xx << ", yy = " << yy << '\n';
>     return 0;
> }
> ```

#### 3.4.2.1 Объявление шаблона. Ключевые слова `typename` и `class`

> [!quote] Документация и стандарт по теме
> - Шаблон функции: https://cppreference.com/cpp/language/function_template
> - Стандарт, шаблоны функций: https://eel.is/c++draft/temp.fct

Для объявления параметров-типов шаблона используются ключевые слова `typename` и `class`. Вместо префикса `template<typename T>` можно использовать префикс `template<class T>`. Эти две конструкции означают одно и то же.

```cpp
template<typename T>
T findMax(T a, T b);

template<class T>
T findMax(T a, T b);
```

Если использовать ключевое слово `class`, то фактический тип не обязательно должен быть классом: это может быть фундаментальный тип, указатель или любой другой тип.

> [!important] Параметры шаблона функции — константные ссылки
> Поскольку тип аргумента функции, передаваемый в тип `T`, может быть классом, а классы, как правило, не рекомендуется передавать по значению, то лучше сделать параметры и возвращаемое значение нашего шаблона функции константными ссылками:
> ```cpp
> template<typename T> const T& findMax(const T& a, const T& b)
> {
>     return (a >= b ? a : b);
> }
> ```
> Эта версия заменяет `T findMax(T a, T b)`, а не дополняет её: если объявить обе, вызов `findMax(a, b)` станет неоднозначным, и компилятор сообщит `call to 'findMax' is ambiguous`.
