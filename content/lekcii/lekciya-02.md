## 1.1.1.1 Язык программирования

> [!note] Программирование
> процесс создания и изменения компьютерных программ и алгоритмов.

Результат программирования — **программа**: записанная на понятном исполнителю языке последовательность команд, решающая некоторую задачу. Исполнителем чаще всего выступает компьютер (ЭВМ), и здесь возникает главная трудность: компьютер не понимает естественные языки. Русский или английский полны неоднозначностей — одна и та же фраза может быть понята по-разному в зависимости от контекста, интонации, порядка слов. Команда для машины таких вольностей не допускает: она должна пониматься строго единственным образом. Поэтому для записи программ используют **формальные языки** — языки, все правила которых заданы точно и исчерпывающе.

> [!note] Язык программирования
> формальный язык, предназначенный для записи компьютерных программ.

> [!quote]
> «Язык образует среду мышления и формирует представление о том, о чём мы думаем» — Б. Л. Уорф [18, предисловие к первому изданию]

Эта мысль высказана лингвистом Бенджамином Ли Уорфом о естественных языках: язык, на котором мы говорим, незаметно определяет, *как* мы думаем и какие мысли нам вообще доступны. Бьярне Страуструп не случайно выбрал её эпиграфом к книге о C++ — к языкам программирования она относится в полной мере. Понятия языка, которым владеет программист, становятся понятиями, которыми он мыслит задачу: тот, кто знает только циклы и массивы, любую задачу раскладывает на циклы и массивы; владеющий функциями, классами и готовыми алгоритмами видит в той же задаче совсем другие, более короткие решения. Поэтому изучение нового языка — и шире, новой парадигмы программирования — расширяет не словарный запас, а само мышление разработчика.

Язык программирования определяет набор **лексических**, **синтаксических** и **семантических** правил, определяющих внешний вид программы и действия, которые выполнит исполнитель (обычно — ЭВМ) под её управлением. Подробно эти три группы правил разобраны в §1.1.1.2 «Алфавит, лексика, синтаксис и семантика языка C++».

Языки программирования принято делить по «расстоянию» от процессора:

- **машинный код** — числовые команды, которые процессор исполняет непосредственно; писать и читать их человеку крайне тяжело;
- **язык ассемблера** — те же команды процессора, но записанные мнемониками (`mov`, `add`, `jmp`); привязан к конкретному семейству процессоров;
- **языки высокого уровня** (C++, Python, Java и др.) — оперируют понятиями, близкими к человеческой записи алгоритма: переменные, функции, циклы. Программа на таком языке не зависит от конкретного процессора, но требует перевода в машинный код — этим занимается компилятор или интерпретатор (см. §1.1.2.2 «Написание, компиляция и выполнение программ»).

Покажем эту разницу на примере. Рассмотрим простейшую функцию — возведение целого числа в квадрат.

**Язык высокого уровня (C++).** Запись близка к математической:

```cpp
int square(int num) {
    return num * num;
}
```

**Язык ассемблера (x86-64).** То же самое, но уже командами процессора:

```nasm
square(int):
        mov     eax, edi        ; скопировать аргумент из регистра edi в регистр eax
        imul    eax, edi        ; eax = eax * edi — собственно умножение
        ret                     ; вернуть управление; результат остался в eax
```

Здесь нет ни имени `num`, ни типа `int`, есть только **регистры** процессора (`eax`, `edi`) и негласная договорённость: первый аргумент функции приходит в `edi`, результат возвращается в `eax`.

**Машинный код.** Те же три команды, но так, как они на самом деле лежат в памяти, — числами (шестнадцатеричными):

```
89 F8
0F AF C7
C3
```

Соответствие построчное: `89 F8` — это `mov eax, edi`, `0F AF C7` — `imul eax, edi`, `C3` — `ret`. Вся функция занимает 6 байт. Язык ассемблера — **не отдельный язык поверх машинного кода, а его человекочитаемая запись**, мнемоника вместо чисел.

Если скомпилировать *тот же самый* исходный текст для процессора архитектуры ARM (Apple M-серии, смартфоны):

```nasm
square(int):
        mul     w0, w0, w0      ; машинный код: 0x1B007C00
        ret                     ; машинный код: 0xD65F03C0
```

C++-текст не изменился ни на символ, а машинные команды получились совершенно другие: другие имена регистров (`w0` вместо `eax` / `edi`), другой набор инструкций, другая длина команд — в ARM каждая команда занимает ровно 4 байта, тогда как в x86-64 наши три команды заняли 2, 3 и 1 байт. Именно это и означает фраза «язык высокого уровня не зависит от процессора»: переносится **исходный текст**, а не результат его компиляции.

> [!example] Попробуйте сами
> Откройте Compiler Explorer ([godbolt.org](https://godbolt.org)) [37] и вставьте функцию `square` в левое окно — справа сразу появится ассемблерный код, причём строки исходника и ассемблера подсвечиваются одним цветом. Полезные настройки: выбрать компилятор **x86-64 gcc**, дописать в поле флагов `-O2` (без оптимизации компилятор добавит служебные команды `push rbp` / `mov rbp, rsp` / `pop rbp`), включить в меню вывода **Intel syntax**, а чтобы увидеть машинный код в байтах — **Compile to binary object**. Смените компилятор на **ARM64 gcc** — и убедитесь, что получится второй вариант.

> [!abstract] Повышенный уровень
> Структура есть даже внутри отдельного байта. Команда `mov eax, edi` — это `89 F8`, где первый байт `89` — код операции «переслать 32-битное значение из регистра в регистр», а второй байт `F8` (в двоичном виде `11 111 000`) уточняет, какие именно регистры: `11` — оба операнда регистры, `111` — ист…

## 1.1.1.2 Алфавит, лексика, синтаксис и семантика языка C++

> [!note] Документация
> <https://cppreference.com/cpp/language/charset>

> [!note] Стандарт
> <https://eel.is/c++draft/lex>

Формальный язык устроен по тем же «этажам», что и естественный: из букв складываются слова, из слов — предложения, а у предложений есть смысл. В языке программирования этим этажам соответствуют алфавит, лексика, синтаксис и семантика.

> [!note] Алфавит языка
> конечный набор допустимых символов, из которых строятся все конструкции языка:
>
> - буквы латинского алфавита (`a–z`, `A–Z`),
> - цифры (`0–9`),
> - знаки препинания и специальные символы (`{ } ( ) [ ] ; , . : ? ' " ~ | / \ ^ ! = < > + - * % & _ #` и др.), а также
> - пробельные символы (пробел, табуляция, перевод строки).

Регистр букв в C++ значим: `count`, `Count` и `COUNT` — три разных имени, а функцию `main` нельзя назвать `Main`.

> [!note] Лексика языка (лексические правила)
> правила, определяющие, как из символов алфавита складываются минимальные значащие единицы языка — лексемы (токены).

Идентификаторы, ключевые слова, литералы, знаки операций, разделители являются примерами лексем (токенов). Подробнее о литералах — см. §1.1.3.2 «Литералы», об идентификаторах и ключевых словах — §1.1.3.3 «Имена — идентификаторы и ключевые слова». Термины «лексема» и «токен» в повседневной речи программистов употребляются как синонимы — «слово» языка программирования. Строго говоря, они называют две стороны одного и того же:

> [!note] Лексема
> (от греч. *léxis* — слово) минимальная значащая последовательность символов исходного текста программы: конкретная цепочка символов.

Примеры лексем: `count`, `int`, `10`, `=`, `;`.

> [!note] Токен
> (от англ. *token* — знак, ярлык) результат распознавания лексемы лексическим анализатором компилятора: пара «категория + значение».

Например «идентификатор `count`», «ключевое слово `int`», «литерал `10`», «операция `=`».

Иначе говоря, лексема — это сам текст, а токен — его «ярлык» с указанием категории. Компилятор читает программу не по символам, а именно по токенам: для проверки синтаксиса ему важно, что `count` — идентификатор, а `10` — литерал, а не то, из каких букв и цифр они состоят. В материалах курса оба термина используются взаимозаменяемо.

> [!note] Токенизация (лексический анализ)
> процесс разбиения исходного текста программы на токены.

**Инструкция**

```cpp
int count = 10;
```

состоит из пяти лексем: `int` — ключевое слово (имя типа), `count` — идентификатор (имя переменной), `=` — знак операции, `10` — литерал (запись значения в тексте программы), `;` — разделитель. Пробелы между лексемами компилятор отбрасывает — они лишь отделяют лексемы друг от друга.

Подробнее о типах данных, переменных, литералах см. §1.1.3.1 «Фундаментальные типы данных и другие типы данных C++».

> [!note] Синтаксис языка (синтаксические правила)
> совокупность формальных правил, определяющих, какие последовательности символов алфавита образуют допустимые (правильно построенные) конструкции языка — операторы, выражения, объявления.

Нарушение синтаксиса — синтаксическая ошибка: компилят…

```
title Фаза анализа (frontend)
Лексический анализ: текст на токены
Синтаксический анализ: токены соответствуют правилам грамматики
Семантический анализ: смысл конструкций
```

- **Лексический анализ** — разбивает текст программы на токены: ключевые слова, идентификаторы, литералы, знаки операций, разделители; пробелы и комментарии при этом отбрасываются.
- **Синтаксический анализ** — проверяет, что последовательность токенов соответствует правилам грамматики C++, и строит по ней **абстрактное синтаксическое дерево (AST)** — внутреннее представление структуры программы.
- **Семантический анализ** — проверяет смысл построенных конструкций: согласованность типов данных, области видимости имён, соответствие аргументов вызовов объявлениям функций.

Ошибка на любом из трёх этапов останавливает компиляцию — исполняемый файл не будет создан, пока программист её не исправит (см. §1.5.3.1 «Типы ошибок»).

## 1.1.1.3 Структура программы

> [!note] Стандарт
> <https://eel.is/c++draft/basic.start.main>

Для того чтобы программу можно было скомпилировать и запустить, она должна иметь определённую структуру. Стандарт C++ требует, чтобы в программе была единственная глобальная функция `main` — назначенное начало программы, её **точка входа**.

> [!note] Точка входа (entry point)
> место в программе, с которого операционная система начинает её выполнение после запуска. Как именно устроена точка входа — зависит от языка программирования и платформы.

`main` — это функция: именованный фрагмент программы с алгоритмом внутри (см. §1.1.1.4 «Базовое понятие функции и проверка работы функции»); особенная она лишь тем, что её имя фиксировано стандартом, а вызывает её не программист, а среда выполнения при запуске.

> [!abstract] Повышенный уровень
> В соответствии со стандартом C++, `main` — точка входа на уровне языка C++, а не на уровне операционной системы. Что происходит до вы…

Минимальная программа на C++ (тело функции пусто или состоит из одной инструкции), имеет вид:

> [!example] Сниппет 1.1 — Минимальная программа на C++
> ```cpp
> // вариант без return — допустим только для main
> int main()
> {
>     // ваш код
> }
>
> // вариант с явным return
> int main()
> {
>     // ваш код
>     return 0;
> }
> ```

Классическим примером первой программы на любом языке программирования является программа «Hello, World!»:

> [!example] Сниппет 1.2 — Программа «Hello, World!»
> ```cpp
> #include <iostream>
>
> int main()
> {
>     std::cout << "Hello, World!";
> }
> ```
>
> Результат её выполнения:
>
> ```
> Hello, World!
> ```

Её структура:

- `#include <iostream>` — директива препроцессора, подключающая библиотеку `iostream`;
- `int main()` — заголовок функции `main`;
- `{ }` — фигурные скобки обозначают начало и конец тела функции;
- `std::cout << "Hello, World!";` — инструкция, выводящая строку в стандартный поток вывода.

> [!example] Сниппет 1.3 — Функция `main` с параметрами — для приёма аргументов командной строки
> ```cpp
> int main(int argc, char* argv[])
> {
>     // argc — количество аргументов
>     // argv — массив строк-аргументов
>     return 0;
> }
> ```

Пока достаточно формы без параметров `int main()`; подробнее об аргументах функции `main` см. §1.4.2.1 «Функция main, передача параметров в функцию main».

Программа на языке C++ имеет следующую **структуру**:

1. **директивы препроцессора** (`#include`, `#define` и др.) — команды, которые обрабатываются ещё до компиляции: например, `#include` подключает к программе заголовочные файлы библиотек;
2. **задание пространства имён** (`namespace`) — способ сгруппировать имена и защитить их от совпадений;
3. **глобальные описания** — объявление переменных, констант и функций вне всех функций, видимых всему файлу;
