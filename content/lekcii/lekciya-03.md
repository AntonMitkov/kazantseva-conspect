## 1.1.1.4 Базовое понятие функции и проверка работы функции

### Вводный пример

Программа с функциями `sum` и `difference` (для `product`, `quotient`, `remainder` — аналогично: `*`, `/`, `%`):

```cpp
#include <iostream>

// объявление функций
int sum(int a, int b);
int difference(int a, int b);
// product, quotient, remainder — аналогично: *, /, %

// точка входа
int main()
{
    std::cout << "Введите первое число: ";
    int a;
    std::cin >> a;
    std::cout << "Введите второе число: ";
    int b;
    std::cin >> b;

    std::cout << "Сумма: "   << sum(a, b)        << '\n';
    std::cout << "Разность: " << difference(a, b) << '\n';
    // ...
    return 0;
}

// определение функций
int sum(int a, int b)
{
    return a + b;
}

int difference(int a, int b)
{
    return a - b;
}

// product, quotient, remainder — аналогично: *, /, %
```

Прежде чем использовать функции в программе, было бы хорошо проверить правильность их работы. Напишем для этого <!-- TODO: конец фразы обрезан на фото -->

**Шаг 3.** Теперь каждую функцию можно проверить: пишем функции тестирования и вызываем их в начале `main`; каждая проверяет свою функцию на четырёх видах ситуаций — типичной, граничной, «±1 от границы» и «неудобной». Для деления добавляем предусловие:

```cpp
#include <cassert>
#include <iostream>

// объявление функций
int sum(int a, int b);
int difference(int a, int b);
int product(int a, int b);
int quotient(int a, int b);
int remainder(int a, int b);

// функции тестирования: типичный случай, граница, ±1 от границы, «неудобный» случай
void testSum()
{
    assert(sum(7, 2) == 9);
    assert(sum(0, 0) == 0);
    assert(sum(0, 1) == 1);   // ±1 от границы
    assert(sum(0, -1) == -1);
    assert(sum(-3, 3) == 0);

    // сумма коммутативна: от перестановки слагаемых результат не меняется
    assert(sum(2, 7) == 9);
    assert(sum(1, 0) == 1);   // ±1 от границы
    assert(sum(-1, 0) == -1);
    assert(sum(3, -3) == 0);
}

void testDifference()
{
    assert(difference(7, 2) == 5);
    assert(difference(5, 5) == 0);
    assert(difference(1, 0) == 1);   // ±1 от границы
    assert(difference(0, 1) == -1);
    assert(difference(2, 7) == -5);
}

void testProduct()
{
    assert(product(7, 2) == 14);
    assert(product(0, 99) == 0);
    assert(product(1, 5) == 5);    // ±1 от границы: умножение на ±1
    assert(product(-1, 5) == -5);
    assert(product(-3, 4) == -12);

    // произведение коммутативно: от перестановки множителей результат не меняется
    // ...
}
```

> [!warning] Пропуск
> На фотографиях далее не поместились функции `testQuotient`, `testRemainder` и `main`, вызывающий все тесты. Дозаписать со следующих снимков.

### Теория

Теперь рассмотрим теоретические основы того, что мы рассмотрели в примере.

> [!note] Функция
> сущность C++, которая связывает последовательность инструкций (тело функции) с именем и списком нулевых или более *параметров функций*.

Функция является именованным фрагментом программы, который принимает входные данные (параметры), выполняет заданный алгоритм и возвращает результат (инструкцией `return`). Функция вызывается по имени из других частей программы; одну и ту же функцию можно вызывать многократно с разными аргументами.

> [!tip]
> Вся исполняемая часть программы находится внутри функций.

Минимальная форма определения функции:

```cpp
тип_результата имя(тип параметр1, тип параметр2) {
    // алгоритм
    return результат;
}
```

### Объявление и определение функции

Ключевое правило C++: любое имя должно быть **объявлено до первого использования** — компилятор читает файл сверху вниз и не заглядывает вперёд. Поэтому у каждой функции, кроме `main`, различают две записи:

> [!note] Объявление (прототип) функции
> предварительное описание функции для компилятора: тип возвращаемого значения, имя и список параметров, завершённые точкой с запятой — без тела:
>
> ```cpp
> double incomeTax(double income);
> double incomeTax1(double); // допустимо опускать имена параметров
> ```

> [!abstract] Определение (реализация) функции
> полное описание функции: заголовок вместе с телом в фигурных скобках. Определение одновременно является и объявлением. Каждая функция определяется в программе ровно один раз.

Разделение объявления и определения позволяет размещать реализацию функции где угодно — например, после `main`: для компиляции вызова достаточно прототипа, а связывание вызова с реализацией выполнит компоновщик (см. §1.3.2 «Написание, компиляция и выполнение программ»). Именно на этом разделении строятся многомодульные программы: в заголовочные файлы попадают объявления, а реализации живут в отдельных файлах с исходным кодом, см. §07 <!-- TODO: ссылка/номер обрезаны на фото -->

### Проверка работы функции утверждениями

Для того, чтобы убедиться, что написанная функция работает правильно, можно использовать инструмент самого языка — **проверку утверждений** из заголовочного файла `<cassert>`.

> [!note] Утверждение (assertion)
> условие, которое, по замыслу программиста, обязано быть истинным в данной точке программы. Проверка `assert(условие)` из `<cassert>` вычисляет условие: если оно истинно, программа продолжает работу; если ложно — немедленно завершается с сообщением, в каком месте какое утверждение нарушено.

> [!example] Сниппет 1.5 — Функция и её проверка утверждениями
> ```cpp
> #include <cassert>
> #include <iostream>
>
> // Функция: принимает два числа, возвращает их сумму
> int sum(int a, int b) {
>     return a + b;
> }
> ```

## 1.1.1.5 Библиотеки и заголовочные файлы

> [!note] Документация
> <https://cppreference.com/cpp/standard_library> · <https://cppreference.com/cpp/preprocessor/include>

> [!note] Стандарт
> <https://eel.is/c++draft/headers> · <https://eel.is/c++draft/cpp.include>

Даже простейшая программа не пишется «с нуля»: вывод текста на экран, чтение с клавиатуры, вычисление квадратного корня — всё это готовые средства, которые язык предоставляет программисту. Такие средства оформляются в библиотеки.

> [!note] Библиотека
> набор готовых функций, классов и других средств языка, оформленных для многократного использования.

Часть библиотек описана в самом стандарте языка и поставляется вместе с любым компилятором — это **стандартная библиотека C++**. Помимо неё существуют сторонние библиотеки (графика, работа с сетью, тестирование) и библиотеки, которые программист создаёт сам.

Чтобы воспользоваться средствами библиотеки, её заголовочный файл подключают директивой `#include`:

> [!example] Сниппет 1.6 — Подключение заголовочных файлов
> ```cpp
> #include <имя_файла> // искать в системных каталогах компилятора
> #include "имя_файла" // искать в каталоге текущего проекта
> ```

Угловые скобки `<>` используют для стандартной библиотеки C++ и сторонних библиотек, кавычки `""` — для собственных заголовочных файлов проекта. Собственные заголовочные файлы рассматриваются в курсе при изучении многомодульных приложений (§2.3 «Многомодульные приложения») — тогда обе формы записи подключения заголовочных файлов встанут рядом в одной программе.

> [!note] Заголовочный файл
> файл с объявлениями средств библиотеки (функций, классов, констант), который подключается к программе директивой `#include` и делает эти средства доступными в ней.

При разработке библиотек используется то же разделение объявления и определения, что и у обычных функций (см. §1.1.1.4 «Базовое понятие функции и проверка работы функции»). <!-- TODO: конец абзаца обрезан на фото -->

### Обзор возможностей стандартной библиотеки C++

> [!note] Стандартная библиотека C++ (standard library)
> набор готовых средств, описанных в стандарте языка и поставляемых с каждым компилятором. Доступ к средствам открывается подключением соответствующего заголовочного файла; почти все имена стандартной библиотеки живут в пространстве имён `std`.

Стандартная библиотека C++ состоит из нескольких десятков заголовочных файлов (в C++23 — более сотни), сгруппированных по назначению:

- **ввод-вывод** — `<iostream>`, `<fstream>` (файлы), `<iomanip>` (форматирование);
- **строки** — `<string>` и средства их обработки;
- **контейнеры** — `<vector>`, `<array>`, `<map>` и др.;
- **алгоритмы и итераторы** — `<algorithm>`, `<iterator>`;
- **математика и числа** — `<cmath>`, `<numbers>` (математические константы, C++20), `<numeric>`, `<limits>`;
- **диагностика** — `<cassert>`, `<stdexcept>` (исключения);
- **утилиты общего назначения** — `<utility>`, `<functional>`, `<chrono>` (время);
- **C-совместимые заголовки** — `<cstdlib>`, `<cctype>` и другие вида `<c...>`.

Полная карта заголовков — на cppreference: Standard library headers. Осваивать её сразу целиком не нужно: библиотека изучается по мере надобности — контейнеры и алгоритмы начнут появляться с раздела 2, а подробно структура стандартной библиотеки разбирается в теме §6.1 «Структура стандартной библиотеки и стандартной библиотеки шаблонов». Более подробно на этом этапе рассмотрим четыре библиотеки:

- `<iostream>` — библиотека потокового ввода-вывода: содержит объекты `std::cin` (стандартный ввод) и `std::cout` (стандартный вывод);
- `<cmath>` — библиотека математических функций: `std::sqrt`, `std::pow`, `std::abs`, `std::sin`, `std::cos` и др.;
- `<numbers>` — библиотека готовых математических констант (C++20). Она избавляет от необходимости писать их вручную. Все константы находятся в пространстве имён `std::numbers`.
- `<cassert>` — проверка утверждений `assert`, уже знакомая по §1.1.1.4 «Базовое понятие функции и проверка работы функции».

### Математические библиотеки

> [!warning] `<cmath>` vs `<math.h>`
> В интернет-примерах встречается подключение `#include <math.h>` — это заголовок, унаследованный из языка C. Он работает, но в C++ принято подключать C-совместимые заголовки в форме `<c...>` без `.h`: `<cmath>`, `<cstdlib>`, `<cctype>`. Именно эта форма гарантированно помещает функции в пространство имён `std`.

В библиотеке `<math.h>` (и, как следствие, в `<cmath>`) математические константы — `M_PI` (число π), `M_E` (число e) и другие — заданы **макросами**.

> [!note] Макрос (macro)
> именованный фрагмент текста, определяемый директивой препроцессора `#define`: препроцессор заменяет каждое вхождение имени макроса его текстом ещё до начала компиляции. Макрос — чисто текстовая подстановка: у него нет ни типа, ни области видимости.

> [!warning] `M_PI` — не стандарт C++
> Констант `M_PI`, `M_E` и родственных в стандарте C++ нет — это расширение POSIX, и переносимость кода с ними не гарантирована. GCC и Clang обычно объявляют их сразу, а в Visual Studio (MSVC) они доступны, только если определить макрос `_USE_MATH_DEFINES` строго до включения `<cmath>`:
>
> ```cpp
> #define _USE_MATH_DEFINES // обязательно ДО include, иначе не сработает
> #include <cmath>
> ```
>
> Определять константы собственными макросами (`#define PI 3.14159`) — тоже анти-паттерн по меркам курса: у макроса нет ни типа, ни области видимости, а именованные константы объявляются `constexpr` (пункт 13 §0.8 «Основы Code Style»).

Начиная с C++20 эта проблема решена стандартно: заголовок `<numbers>` предоставляет математические константы как типизированные `constexpr`-переменные в пространстве имён `std::numbers` — `pi`, `e`, `sqrt2`, `ln2`, `phi` (золотое сечение) и другие. Именно эта форма принята в курсе:

> [!example] Сниппет 1.7 — Число π из `<numbers>` (C++20)
> ```cpp
> #include <numbers>
>
> double circleArea(double r) // площадь круга радиуса r
> {
>     return std::numbers::pi * r * r;
> }
> ```

> [!info] Современный C++
> Начиная с C++20 у директивы `#include` есть современная альтернатива — модули (`import`), а в C++23 вся стандартная библиотека подключается одной строкой `import std;`. Модули обзорно рассматриваются в теме §2.3; о развитии языка — см. §1.7 «Современное положение языка C++».

## 1.1.1.6 Комментарии

### Виды комментариев в C++

> [!note] Комментарий
> фрагмент текста программы, который полностью игнорируется компилятором и предназначен для человека — пояснение к коду для его читателей (в том числе для будущего себя).

Комментарии отбрасываются на самом раннем этапе обработки исходного текста, поэтому они никак не влияют ни на размер исполняемого файла, ни на скорость работы программы — писать их можно и нужно свободно.

В C++ два вида комментариев:

1. **однострочный комментарий** (line comment) `//` — основной в современном C++: им оформляют и пояснения на отдельной строке, и короткие заметки после инструкции. Отбрасывает всё, начиная с того места, где находится пара знаков косой черты (`//`), до конца той же строки;
2. **многострочный комментарий** (block comment) `/* ... */` удобен для длинных пояснений и для временного «выключения» фрагмента кода. Отбрасывает всё между символами `/*` и первым появлением символов `*/`, с возможностью включения нескольких строк.

Внутри `/* ... */` допустимо любое количество любых символов (кроме `*/`; вложить комментарий в комментарий нельзя), поэтому таким комментарием удобно оформлять заметные блоки-шапки. Типичное применение — шапка файла лабораторной работы:

```cpp
/**********************************************
 * Лабораторная работа № 1, задание 3         *
 * Тема: функции и проверка утверждений        *
 * Выполнил: Иванов И. И., группа 1            *
 **********************************************/
```

Звёздочки по краям — просто украшение для читаемости: для компилятора комментарий начинается на `/*` и заканчивается на первом же `*/`.

### Какие комментарии считать хорошими

Комментарий должен сообщать то, чего не видно из самого кода: **зачем** так написано, а не **что** делает строка. Пересказ кода своими словами — шум, который устаревает при первом же изменении программы.

> [!example]- Плохой и хороший комментарий
> ```cpp
> ++attempts;   // увеличиваем attempts на 1 — плохо: пересказ кода
>
> ++attempts;   // хорошо: пояснение причины
> // по условию задачи первая попытка тоже считается использованной
> ```

Ещё лучше — писать код, которому почти не нужны комментарии (**самодокументирующийся код**): понятные имена переменных и функций (`attempts`, `incomeTax`) говорят сами за себя.

В учебных программах курса комментарии обязательны там, где решение неочевидно: формула из условия задачи, неочевидное ограничение, причина выбора типа данных. Эти же пояснения переносятся в код-сниппеты рабочей тетради (см. §0.2 «Рабочая тетрадь»).

> [!info] Документирование кода: Doxygen
> У комментариев есть ещё одна роль — по ним можно автоматически строить справочную документацию. Инструмент **Doxygen** [39] читает *документирующие комментарии* — комментарии особого вида `///` или `/** ... */`, записанные перед объявлением функции, класса или константы, — и генерирует по ним документацию ко всему проекту (HTML-страницы, PDF). Внутри таких комментариев используются теги: `@brief` — краткое назначение, `@param` — описание параметра, `@return` — возвращаемое значение.
>
> ```cpp
> /// @brief Вычисляет подоходный налог.
> /// @param income доход до налогообложения, руб.
> /// @return сумма налога по ставке 13 %
> double incomeTax(double income);
> ```
>
> Документирующий комментарий пишут перед объявлением — как правило, в заголовочном файле, рядом с прототипом (см. §1.1.1.5 «Библиотеки и заголовочные файлы»). Эти же комментарии понимает IDE: описание функции всплывает подсказкой прямо при наборе вызова.
