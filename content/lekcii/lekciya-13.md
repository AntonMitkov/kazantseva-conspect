## 1.3.3 Способы передачи параметров в функцию (продолжение)

Пример 1.59 — см. [[lekciya-12#Три способа передачи|Лекцию 12]]. Тела трёх функций по сути одинаковы, но результат разный: `swapByValue` меняет местами свои копии `a` и `b`, а `x` и `y` остаются прежними. `swapByReference` работает с самими `x` и `y`. `swapByPointer` получает адреса `x` и `y` и меняет значения по этим адресам; при вызове адреса берутся явно — `&x`, `&y`.

> [!abstract] Передача по значению (pass by value)
> способ передачи, при котором параметр — отдельный объект, инициализируемый значением аргумента; изменения параметра внутри функции не влияют на аргумент.

> [!abstract] Передача по ссылке (pass by reference)
> способ передачи, при котором параметр — ссылка, привязанная к аргументу; все действия с параметром выполняются над самим аргументом.

> [!abstract] Передача по указателю (pass by pointer)
> разновидность передачи по значению, при которой параметру-указателю передаётся адрес объекта; функция может изменить объект через разыменование указателя.

Но на самом деле стандарт C++ вообще не называет «способов передачи параметров». Выражения «pass by value» и «pass by reference» — термины учебников и руководств, в нормативном тексте их нет. Стандарт описывает только одно правило ([expr.call]/7): при вызове функции каждый параметр инициализируется соответствующим аргументом (copy-initialization, [dcl.init]). Дальше всё зависит от типа параметра:

- параметр — ссылка (`T&`, `const T&`, `T&&`; ссылки `T&&` разобраны в теме 3.3 «Ссылки, указатели и динамическая память»). Ссылка привязывается к аргументу по правилам [dcl.init.ref], и копии объекта не создаётся;
- параметр — объект любого другого типа. Создаётся новый объект — параметр, — и он инициализируется значением аргумента. Указатель `T*` — обычный объектный тип (скалярный, как `int` или `double`). Поэтому параметр `int* p` инициализируется копией адреса точно так же, как `int x` — копией числа.

> [!tip] С точки зрения языка способов передачи аргументов два:
> - параметр-объект («по значению») и
> - параметр-ссылка («по ссылке»).

«Передача по указателю» — это не механизм языка, а приём: адрес передаётся по значению. Поэтому список из трёх способов неточен: передача по указателю — не третий механизм, а разновидность передачи по значению.

Так как копируется адрес, функция может изменить объект, на который указывает указатель, но не сам указатель вызывающего кода: если внутри `swapByPointer` присвоить `a = nullptr;`, изменится лишь копия адреса. Изменить указатель вызывающего кода позволяет указатель на указатель (см. [[lekciya-06|1.1.2.6.4 Указатель]]) или ссылка на указатель.

> [!info] Почему передачу по указателю выделяют отдельно
> Передача по указателю всё же выделяется отдельно, поскольку это устойчивый приём со своими свойствами: доступ к объекту вызывающего кода через разыменование, возможность передать `nullptr` («объекта нет»), явный `&` (оператор взятия адреса) в месте вызова. Этот приём унаследован из C, где передачи по ссылке нет и только так функция может изменить объект вызывающего кода. Core Guidelines тоже рассматривают `T*` отдельно (F.60: «Предпочитайте `T*` вместо `T&`, если „аргумента нет“ — допустимый вариант»), но не как особый механизм языка.

Обычную (неконстантную) ссылку можно привязать только к lvalue (см. [[lekciya-09#1.2.3.2 Выражения|1.2.3.2 Выражения]]), а не к rvalue — например, к литералу `5` или результату `x + 1`. Для функции `increase` из [[lekciya-06|1.1.2.6.3 Ссылка]]:

```cpp
void increase(int& x)
{
    x += 1;
}

int main()
{
    increase(5); // ошибка: 5 — rvalue
}
```

### Константные параметры

При передаче по значению объект копируется при каждом вызове. Для `int` или `double` это дёшево, а копирование длинной строки `std::string` или большой структуры требует времени и памяти. Передача по ссылке копирования избегает, но даёт функции право изменить аргумент. Если функция аргумент только читает, параметр объявляют **ссылкой на константу** — `const T&`: копирования нет, а изменить аргумент компилятор не позволит.

> [!example] Пример 1.60 — Передача строки по ссылке на константу
> ```cpp
> #include <iostream>
> #include <string>
>
> int countVowels(const std::string& text)
> {
>     int count = 0;
>     for (char symbol : text) {
>         switch (symbol) {
>         case 'a':
>         case 'e':
>         case 'i':
>         case 'o':
>         case 'u':
>             ++count;
>             break;
>         default:
>             break;
>         }
>     }
>     return count;
> }
> // TODO: main примера на фото не попал
> ```

> [!example] Пример 1.61 — Необязательный параметр-указатель
> ```cpp
> #include <iostream>
>
> bool divide(int dividend, int divisor, int* quotient)
> {
>     if (divisor == 0 || quotient == nullptr) {
>         return false;
>     }
>     *quotient = dividend / divisor;
>     return true;
> }
>
> int main()
> {
>     int result = 0;
>     if (divide(17, 5, &result)) {
>         std::cout << result << '\n'; // 3
>     }
>     std::cout << divide(17, 0, &result) << '\n'; // 0 — деление невозможно
> }
> ```

### Выбор способа передачи параметра

Способ передачи выбирают по тому, что функция делает с аргументом. Правила ниже следуют рекомендациям F.15–F.17 и F.60 C++ Core Guidelines.

> [!quote] C++ Core Guidelines о передаче параметров (F.15–F.17, F.60)
> - **F.15**: Предпочитайте простые и общепринятые способы передачи информации.
> - **F.16**: Для входных параметров передавайте типы, которые дёшево копировать, по значению, а остальные — по ссылке на `const`. Что «дёшево копировать», зависит от архитектуры, но объекты размером в два-три машинных слова (`double`, указатели, ссылки) обычно лучше передавать по значению.
> - **F.17**: Для параметров, которые функция читает и изменяет, используйте ссылку на не-`const`.
> - **F.60**: Предпочитайте `T*` вместо `T&`, если отсутствие аргумента — допустимый вариант: указатель может быть `nullptr`, а «нулевой ссылки» не существует.

### Возвращение ссылок и указателей

## 1.3.4 Стек вызовов и кадр стека

> [!quote] Документация и стандарт по теме
> **Документация:**
> - Вызов функции: <https://cppreference.com/cpp/language/operator_other#Built-in_function_call_operator>
> - Длительность хранения: <https://cppreference.com/cpp/language/storage_duration>
>
> **Стандарт:**
> - Вызов функции: <https://eel.is/c++draft/expr.call>
> - Длительность хранения: <https://eel.is/c++draft/basic.stc>

Разберём, что происходит при вызове функции, на функции `area` из сквозного примера о площади прямоугольника (шаг 3 в [[lekciya-03|1.1.1.4 Базовое понятие функции и проверка работы функции]]). Функция `main` вызывает `area` и сохраняет результат в переменной `roomArea`. Комментарии (1)–(3) в коде отмечают порядок, в котором выполняются строки.

> [!example] Пример 1.64 — Вызов функции приостанавливает вызывающую функцию
> ```cpp
> #include <iostream>
>
> double area(double width, double length)
> {
>     return width * length;               // (2) выполняется area; main ждёт
> }
>
> int main()
> {
>     double roomArea = area(3.0, 4.5);    // (1) вызов: main приостанавливается
>     std::cout << roomArea << '\n';       // (3) после возврата main продолжается: 13.5
> }
> ```

Когда `main` вызывает функцию `area`, выполнение `main` приостанавливается: после возврата из `area` программа должна продолжить `main` с того же места и с теми же значениями переменных. Значит, при каждом вызове где-то нужно сохранить параметры и локальные переменные <!-- TODO: окончание абзаца на фото обрезано -->

> [!abstract] Стек вызовов (call stack)
> область памяти, в которой хранятся данные всех начатых и ещё не завершённых вызовов функций; данные последнего вызова находятся на вершине стека и удаляются первыми.

> [!abstract] Кадр стека (stack frame)
> часть стека вызовов, выделяемая для одного вызова функции; может содержать параметры функции, её локальные переменные и адрес возврата — место в вызывающей функции, с которого продолжится выполнение. Часть параметров и локальных переменных компилятор может хранить не в кадре, а в регистрах процессора.

Функцию, которая инициирует вызов, называют **вызывающей** (caller), а функцию, которая вызывается и выполняется, — **вызываемой** (callee).

При вызове функции на вершине стека создаётся новый кадр; при выходе из функции он удаляется, и выполнение продолжается по адресу возврата в вызывающей функции. Поэтому параметры и локальные переменные создаются заново при каждом вызове (см. [[lekciya-12#1.3.1 Формальные и фактические параметры. Параметры со значениями по умолчанию|1.3.1 Формальные и фактические параметры]]) <!-- TODO: продолжение и пункты 1–3 списка областей памяти на фото не попали -->

> [!info] Повышенный уровень: кадр стека на x86-64 и хвостовая рекурсия
> На процессорах x86-64 вершину стека хранит регистр RSP (stack pointer), начало текущего кадра — регистр RBP (base pointer), адрес следующей выполняемой команды — регистр RIP (instruction pointer). Параметры и локальные переменные функции адресуются смещением относительно RBP или RSP. (В 32-битном x86 эти регистры называются ESP, EBP и EIP.) Шаги вызова и содержимое кадра стека для небольшого примера разобраны в статье <https://textbook.cs161.org/memory-safety/x86.html> (п. 2.8, 32-битный x86).
>
> Если рекурсивный вызов — последнее действие функции, как в `gcdRecursive`, рекурсия называется **хвостовой**. Компиляторы при оптимизации часто превращают хвостовую рекурсию в цикл, и тогда кадры стека не накапливаются. Стандарт C++ этого не гарантирует, поэтому рассчитывать на такую оптимизацию нельзя.

> [!summary] Резюме
> - Каждый вызов функции создаёт на вершине стека вызовов кадр с параметрами, локальными переменными и адресом возврата; при выходе из функции кадр удаляется.
> - Рекурсивная функция вызывает саму себя — непосредственно (прямая рекурсия) или через другие функции (косвенная); для косвенной рекурсии нужен прототип.
> - Рекурсивная функция обязана иметь базовый случай и рекурсивный шаг, приближающий к нему.
> - Глубина рекурсии ограничена размером стека; без базового случая рекурсия приводит к переполнению стека.
