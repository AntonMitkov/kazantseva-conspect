## 1.3.4 Стек вызовов и кадр стека (дополнения)

<!-- TODO: начало абзаца на фото обрезано -->…64 первые аргументы функции обычно передаются в регистрах процессора, поэтому значения `width` и `length` в действительности могут и не попасть в кадр `area`.

> [!warning] Стек и куча — понятия реализации, а не языка
> Стандарт C++ не описывает память программы через понятия «стек» и «куча»; эти слова встречаются в нём в других значениях — раскрутка стека при исключениях, контейнер `std::stack`, алгоритмы `std::make_heap` и `std::push_heap`. Вместо этого стандарт задаёт *длительность хранения* объектов, в частности автоматическую (локальные переменные и параметры), статическую (глобальные и статические переменные) и динамическую (объекты, созданные `new`) — тема 1.6. Схема выше — то, как эти правила обычно реализуют компиляторы и операционные системы.

Содержимое стека вызовов можно увидеть в отладчике: панель «стек вызовов» показывает цепочку вызовов, которая привела к текущей точке программы (см. 2.2.3.3 «Основы отладки программ в IDE — точки останова, стек вызовов, отслеживание переменных»).

Как операционная система выделяет программе стек и от чего зависит его размер — в 1.3.5 доп. «Как операционная система выделяет программе стек».

Рекурсивный вызов создаёт новый кадр стека, как и любой другой вызов: у каждого уровня рекурсии свои параметры и локальные переменные. Чтобы вызовы когда-нибудь закончились, рекурсивная функция должна содержать две части:

- **базовый случай** — ветвь без рекурсивного вызова, которая сразу возвращает результат;
- **рекурсивный шаг** — вызов той же функции с аргументом, приближающим к базовому случаю.

> [!example] Пример 1.65 — Рекурсивное вычисление факториала

>

> {
>     if (n <= 1) {
>         return 1; // базовый случай
>     }
>     return n * factorial(n - 1); // рекурсивный вызов с меньшим аргументом
> }
>
> int main()
> {

### Глубина рекурсии и переполнение стека

Каждый уровень рекурсии занимает в стеке отдельный кадр, а размер стека ограничен — обычно несколько мегабайт (по умолчанию 8 МБ в Linux и macOS, 1 МБ в Windows). ## 1.3.7 Правила проектирования функций

> [!quote] Документация по теме
> - C++ Core Guidelines, раздел F «Функции»: <https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#s-functions>
> - C++ Core Guidelines, раздел I «Интерфейсы»: <https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines#s-interfaces>

Функция даёт имя действию и скрывает подробности его выполнения: чтобы вызвать `area(width, length)`, не нужно знать, как она устроена внутри. Но эта польза есть, только если функция удачно спроектирована — понятно названа, делает одно дело и не зависит от скрытых данных. Ниже собраны правила, которые помогают писать такие функции; большинство из них — рекомендации C++ Core Guidelines [7].

### Правила

1. **Выделяйте осмысленное действие в функцию с говорящим именем** (F.1). Если почти одинаковый код встречается в программе больше одного раза, вынесите его в функцию: исправлять ошибку и менять поведение придётся в одном месте, а вызов функции с хорошим именем не требует поясняющего комментария.
2. **Функция выполняет одно логическое действие** (F.2). Если назначение функции нельзя кратко описать одной фразой — обычно с одним глаголом, — её стоит разделить на несколько.
3. **Делайте функции короткими и простыми** (F.3). Функция должна целиком помещаться на экране; когда она разрастается, выделите её части в отдельные функции.
4. **Не передавайте функции флаги, переключающие её поведение.** Логический параметр, от которого зависит, какое из двух разных действий выполнит функция, делает вызов непонятным; лучше две функции с говорящими именами [31, гл. 3].
5. **Делайте параметров немного** (I.23). Чем больше параметров, тем труднее вызвать функцию правильно — особенно если у нескольких параметров один тип и их легко перепутать местами.
6. **Не используйте изменяемые глобальные переменные** (I.2). Всё, от чего зависит результат функции, передавайте ей параметрами, а результат возвращайте через `return` (F.20, см. [[lekciya-13#1.3.3 Способы передачи параметров в функцию (продолжение)|1.3.3 Способы передачи параметров в функцию]]).
7. **Выбирайте способ передачи параметра по тому, что функция делает с аргументом** (F.15–F.17) — по таблице из 1.3.3 «Способы передачи параметров в функцию».
8. **Не используйте рекурсию там, где цикл проще и не грозит переполнением стека** (см. [[#1.3.5 Рекурсивные функции|1.3.5 Рекурсивные функции]]). Рекурсия уместна, когда задача рекурсивна по своей природе.
9. **Называйте функции глаголами:** `findByName()`, `calcVolume()` — правило оформления кода курса (см. 0.4 «Основы Code Style», п. 4h).

### 1.4.1 Текстовые редакторы, среды разработки

Прежде чем написать первую программу, нужно выбрать инструмент, в котором её писать. Таких инструментов два класса:

- текстовые редакторы и
- интегрированные среды разработки.

> [!abstract] Текстовый редактор (text editor)
> самостоятельная компьютерная программа или компонент программного комплекса, предназначенная для создания и изменения текстовых данных.

Исходный код на C++ — это обычный текст, поэтому писать его можно в любом редакторе. Примеры редакторов, подходящих для программирования: **Visual Studio Code, Sublime Text, Notepad++, Vim / Neovim, Emacs**. Но редактор работает только с текстом: скомпилировать и запустить программу он сам не умеет — эти шаги выполняются отдельными командами в терминале (как именно — см. [[#1.4.2 Написание, сборка и выполнение программ|1.4.2 Написание, сборка и выполнение программ]]).

> [!abstract] IDE (интегрированная среда разработки, Integrated Development Environment)
> комплекс инструментов разработчика, позволяющий не только написать код программы, но и:
> - скомпилировать этот код в готовое приложение;
> - провести тестирование этой программы;
> - выполнить отладку (упрощает поиск ошибок);
> - проводить рефакторинг и другие действия.

В состав современной IDE как отдельные элементы уже входят:

- текстовый редактор (с подсветкой синтаксиса и автодополнением);
- компилятор (или интерпретатор — для интерпретируемых языков программирования);
- отладчик;
- интеграция с системой управления версиями;
- другие инструменты.

### 1.4.3 Этапы сборки программы на C++

C++ — компилируемый язык: перед запуском программа целиком переводится компилятором в машинный код процессора, и пользователь запускает уже готовый исполняемый файл. В интерпретируемых языках (например, Python) исходный текст читается и исполняется интерпретатором строка за строкой при каждом запуске. Компиляция даёт выигрыш в скорости выполнения и позволяет обнаружить многие ошибки ещё до запуска программы.

Пока наша программа состоит из одного исходного файла `*.cpp` (например, `main.cpp`), компиляция выглядит как один шаг: текст программы на входе — исполняемый файл на выходе. **При сборке программы из нескольких файлов этапы компиляции и компоновки выполняются раздельно** — см. 1.4.9 «Раздельная компиляция и компоновка многофайлового проекта».

Исходный C++ файл может быть частью программы или библиотеки. Каждый исходный файл компилируется в объектный файл, а из набора объектных файлов получают исполняемый файл, динамическую или статическую библиотеку. Перевод выполняет компилятор (см. 1.4.5 «Компиляторы»).

Процесс обработки текстовых файлов с кодом на языке C++, который упрощённо называют «компиляцией» (см. определение в [[#1.4.2 Написание, сборка и выполнение программ|1.4.2]]), на самом деле состоит из четырёх этапов (рисунок 1.7):

1. препроцессинга,
2. компиляции,
3. ассемблирования и
4. компоновки (линковки).

Ассемблирование часто относят к компиляции, поэтому говорят и о трёх этапах.

```
Source Code ──► Preprocessing ──► Pre-processed ──► ┌ Compilation ─────────────────┐ ──► Assembly Code ──► Assembly ──► Object Files ──► Linking ──► Executable (.exe)
   .cpp                            Code .ii (.i)    │ Frontend ─AST─► Backend      │      .s (.asm)                    .o (.obj)        ▲          или
                                                    │ (анализ)        (синтез)     │                                                   │      Library .a / .so
                                                    └──────────────────────────────┘                                              Libraries     (.lib / .dll)
```

Что лежит в каждом файле модуля:

- **заголовочный файл** (header file, например `module.hpp`) — прототипы функций, определения констант, объявления глобальных переменных, но только для тех элементов, о которых должны знать другие модули;
- **файл реализации** (source file, например `module.cpp`) — определения функций, глобальных переменных и констант модуля; первой строкой он обычно подключает заголовочный файл своего же модуля: `#include "module.hpp"`.

Модуль, которому нужны функции другого модуля, подключает заголовочный файл этого модуля директивой `#include`. Главный модуль программы обычно содержит только функцию `main` и заголовочного файла не имеет: `main` не вызывается из других модулей. Бывают и модули из одного заголовочного файла — например, с определениями глобальных констант или с шаблонами.

Кроме файлов исходного кода (`*.cpp`) и заголовочных файлов (`*.hpp`), в проект могут входить и другие файлы: описание сборки (например, `CMakeLists.txt`, см. 1.4.10 «Структура учебного проекта»), а в проектах Visual Studio для Windows — файлы ресурсов: значки, курсоры, панели инструментов и другие элементы интерфейса (см. «Файлы ресурсов — Microsoft Learn»).

#### Директива `#include`

Директива `#include` вставляет содержимое указанного файла в точку, где она записана (см. 1.4.3.1 «Препроцессинг»). Так файл получает объявления из другого файла, не копируя их вручную.

```cpp
#include <path-spec> // заголовки стандартной и сторонних библиотек
#include "path-spec" // заголовки своего проекта
```

Спецификация пути (path-spec) — имя файла, перед которым может стоять путь к каталогу. Файл должен существовать; правила записи пути зависят от операционной системы, в которой компилируется программа.

#### Пути поиска заголовочных файлов

Две формы директивы различаются тем, где препроцессор ищет файл. Порядок поиска стандарт оставляет реализации; у g++, clang++ и MSVC он по сути одинаков:

- `#include "имя.hpp"` — сначала в папке файла, который содержит эту директиву, затем в папках, указанных опцией `-I` (у MSVC — `/I`), затем в системных папках стандартной библиотеки;
