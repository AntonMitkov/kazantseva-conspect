## 1.1.2.1 Фундаментальные типы данных C++ (продолжение)

### Целочисленные типы

#### Стандартные целочисленные типы

Существует пять стандартных знаковых целочисленных типов: `signed char`, `short int`, `int`, `long int`, `long long int` — в этом списке каждый тип предоставляет как минимум столько же памяти, сколько предыдущие. Диапазон представимых значений знакового типа шириной N бит — от −2^(N−1) до 2^(N−1) − 1 включительно; почему диапазон именно таков и отчего он несимметричен, объясняет способ кодирования отрицательных чисел — дополнительный код (см. §1.4.2.1 «Представление целых чисел — прямой, обратный и дополнительный код»).

#### Стандартные целочисленные типы с модификаторами

Имя целочисленного типа складывается из базового имени `int` и модификаторов двух групп — знаковости и размера.

**Модификаторы знаковости** задают, отводится ли разряд под знак:

- `signed` — тип знаковый; для всех целых типов, кроме `char`, это и так подразумевается по умолчанию;
- `unsigned` — тип беззнаковый.

Для каждого знакового типа существует парный **беззнаковый**: `unsigned char`, `unsigned short int`, `unsigned int`, `unsigned long int`, `unsigned long long int` — той же ширины N, но с диапазоном от 0 до 2^N − 1. Арифметика беззнаковых типов выполняется по модулю 2^N, поэтому к переполнению не приводит.

**Модификаторы размера** задают минимальную ширину типа:

- `short` — тип оптимизирован по расходу памяти, ширина не менее 16 бит;
- `long` — ширина не менее 32 бит;
- `long long` (C++11) — ширина не менее 64 бит.

Из каждой группы в имени типа допустим только один модификатор: `short long int` — ошибка. А вот порядок слов <!-- TODO: конец фразы на фото обрезан (речь о том, что порядок слов в имени типа произволен: `unsigned long int` = `long unsigned int`) -->

> [!danger] Переполнение знаковой арифметики
> Переполнение знакового целого типа (например, прибавление единицы к максимальному `int`) — неопределённое поведение (UB, см. §1.6.3.4 «Неопределённое поведение (UB)»). Беззнаковая арифметика по модулю переполнением не считается.

### Размеры типов и оператор `sizeof`

Точный размер каждого типа стандарт не фиксирует — гарантируется только цепочка:

```
1 == sizeof(char) ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)
```

> [!note] sizeof
> унарный оператор, возвращающий размер типа или объекта в байтах — точнее, в единицах размера `char` (см. Сниппет 1.11 ниже).

Например, `sizeof(int)` на большинстве современных платформ равен 4.

Реальные размеры зависят от платформы: это **поведение, определяемое реализацией** (implementation-defined). Стандарт требует лишь соблюдения минимумов и цепочки выше, а конкретные значения выбирает разработчик компилятора вместе с моделью данных платформы (LP64, LLP64 и другие — см. ссылку на типы данных в блоке документации в начале параграфа).

**Таблица 1.1 — Размеры некоторых типов данных**

| Тип | Минимум по стандарту, бит | 64-битная Windows (LLP64) | 64-битные Linux/macOS (LP64) |
|---|---|---|---|
| `signed char` | 8 | 8 | 8 |
| `short int` | 16 | 16 | 16 |
| `int` | 16 | 32 | 32 |
| `long int` | 32 | 32 | 64 |
| `long long int` | 64 | 64 | 64 |

Обратите внимание на строку `long` — на Windows и Linux этот тип имеет разный размер; полная таблица моделей данных — по ссылке в документации выше.

> [!example] Сниппет 1.11 — Размеры целочисленных типов на вашей платформе
> ```cpp
> #include <climits>
> #include <iostream>
>
> int main()
> {
>     std::cout << "бит в байте (CHAR_BIT): " << CHAR_BIT << "\n\n";
>
>     std::cout << "sizeof(char)      = " << sizeof(char)      << '\n';
>     std::cout << "sizeof(short)     = " << sizeof(short)     << '\n';
>     std::cout << "sizeof(int)       = " << sizeof(int)       << '\n';
>     std::cout << "sizeof(long)      = " << sizeof(long)      << '\n';
>     std::cout << "sizeof(long long) = " << sizeof(long long) << '\n';
> }
> ```
>
> Вывод на 64-битных Linux и macOS (модель LP64):
>
> ```
> бит в байте (CHAR_BIT): 8
>
> sizeof(char)      = 1
> sizeof(short)     = 2
> sizeof(int)       = 4
> sizeof(long)      = 8
> sizeof(long long) = 8
> ```
>
> На 64-битной Windows (модель LLP64) та же программа напечатает `sizeof(long) = 4`. Строка `long` из Таблицы 1.1 проверяется, таким образом, одним запуском — и именно из-за неё код, где размер важен, не следует писать на `long`.

Две детали, которые видно из этого вывода. Во-первых, `sizeof(char)` равен `1` не «потому что символ занимает байт», а по определению: `sizeof` измеряет размер в единицах размера `char`, поэтому единица у него всегда `char`, каким бы он ни был на платформе. Во-вторых, сколько в этой единице бит, сообщает константа `CHAR_BIT` из заголовочного файла `<climits>`: на всех платформах курса это 8, но стандарт требует лишь «не менее 8».

> [!abstract] Повышенный уровень: гарантии стандарта можно проверить на этапе компиляции
> Полный пример со страницы ключевого слова `long` начинается не с вывода размеров, а с проверок: соблюдены ли на этой платформе минимумы, обещанные стандартом. Приведём его сокращённый вариант — без концептов и шаблонов, которые изучаются позже:
>
> ```cpp
> #include <climits>
> #include <iostream>
>
> // проверка выполнится компилятором — ещё до того, как программа будет запущена
> static_assert(sizeof(long)      >= 32 / CHAR_BIT); // long — не меньше 32 бит
> static_assert(sizeof(long long) >= 64 / CHAR_BIT); // long long — не меньше 64 бит
>
> int main()
> {
>     std::cout << "Standard requirements met! The program compiled successfully.\n";
> }
> ```
>
> `static_assert` — это утверждение, проверяемое **компилятором**, а не при выполнении программы (в отличие от `assert` из §1.1.1.4 «Базовое понятие функции и проверка работы функции»): если условие ложно, программа не собирается вовсе. Записаны здесь те самые минимумы из Таблицы 1.1, которые стандарт обязан обеспечить, пересчитанные из бит в единицы `sizeof` делением на `CHAR_BIT`.
>
> Проверить, что механизм работает, можно заведомо ложным условием — `int` шириной 64 бита не бывает:
>
> ```cpp
> static_assert(sizeof(int) >= 64 / CHAR_BIT, "On this platform, `int` is already 64-bit.");
> ```
>
> Компилятор откажется собирать программу и сошлётся на ваш текст:
>
> ```
> error: static assertion failed due to requirement 'sizeof(int) >= 64 / 8'
>         On this platform, `int` is already 64-bit.
> note: expression evaluates to '4 >= 8'
> ```
>
> В этом и разница между гарантией стандарта и фактическим размером: гарантию проверяет компилятор, ничего не запуская, а фактический размер узнаётся только запуском (Сниппет 1.11).

### Целочисленные типы фиксированной ширины

Как показал Сниппет 1.11, ширина стандартных типов меняется от платформы к платформе. Когда для алгоритма важно, чтобы размер переменной был фиксирован (форматы файлов, сетевые протоколы, точный подсчёт памяти), используют **целочисленные типы фиксированной ширины** из заголовочного файла `<cstdint>`: `std::int32_t`, `std::int64_t` и другие. Это не новые типы, а имена-синонимы (`typedef`) для тех же стандартных типов процессора; заголовок обязателен с C++11, поэтому на любом современном компиляторе эти имена доступны.

Имена устроены единообразно: `std::int8_t`/`std::uint8_t`, `std::int16_t`/`std::uint16_t`, `std::int32_t`/`std::uint32_t`, `std::int64_t`/`std::uint64_t` — число означает ширину в битах, префикс `u` — беззнаковость.

> [!warning] Типы фиксированной ширины стандарт делает необязательными
> Имена `int8_t`, `int16_t`, `int32_t`, `int64_t` существуют в `<cstdint>` только на тех платформах, где у процессора есть целый тип **ровно** такой разрядности, представленный в двоичном дополнительном коде (см. §1.4.2.1 «Представление целых чисел — прямой, обратный и дополнительный код») и без заполняющих битов (padding bits). Если такого типа нет, программа с этим именем просто не скомпилируется.
>
> На практике это ограничение курса не касается. Все распространённые архитектуры (x86, x86-64, ARM, ARM64, RISC-V) используют 8-битный байт (`CHAR_BIT == 8`) и дополнительный код, а с C++20 дополнительный код для знаковых целых закреплён самим стандартом — поэтому `std::int32_t` и `std::int64_t` есть везде, где размер типа кратен 8 битам.

> [!note] Заполняющие биты (padding bits)
> биты в представлении объекта, которые не участвуют в представлении значения: они занимают память, но ничего не хранят.

Пример такого типа в параграфе уже встречался: `bool` занимает целый байт, хотя для двух его значений хватило бы одного бита — остальные семь и есть заполняющие. У целых типов на платформах курса заполняющих битов нет, но стандарт их не запрещает: формально допустим компилятор, у которого `sizeof(int) == 4`, а значащих битов у `int` только 24 — на исторических архитектурах с нестандартной разрядностью машинного слова так и бывало.

Отсюда и требование к типам фиксированной ширины. Имя `std::int32_t` означает не «занимает 32 бита памяти», а «ровно 32 бита, и все они значащие»: только при этом условии гарантировано равенство `sizeof int32_t * CHAR_BIT == 32`. Для обычного `int` такой гарантии нет — поэтому там, где важен каждый бит (формат файла, сетевой пакет, побитовые операции), берут `std::int32_t`, а не `int`.

Исключения из этого правила — то есть платформы, где `std::int8_t` действительно отсутствует, — среди обычных компьютеров не встречаются. Это специализированные процессоры, встраиваемые в приборы и управляющую аппаратуру: сигнальные процессоры (DSP) и некоторые микроконтроллеры (на профессиональном жаргоне разработку под них называют «глубокий эмбеддед», от англ. *deep embedded*). Там байт — а в C++ это минимальная адресуемая единица памяти, а не «ровно восемь бит» — равен 16 или 32 битам: `CHAR_BIT == 16` у семейств TI C2000 и C5000, `CHAR_BIT == 32` у части процессоров SHARC. Отдельного восьмибитного типа на такой платформе просто не существует, поэтому имя `std::int8_t` в `<cstdint>` не объявлено и программа с ним не соберётся, а `std::int_least8_t` — «не менее 8 бит» — окажется 16- или 32-битным и соберётся везде.

### Целочисленные типы минимальной ширины: `least` и `fast`

Там же, в `<cstdint>`, есть два семейства, которые, в отличие от типов фиксированной ширины, **обязательны всегда**:

- `std::int_least#_t` — самый *маленький* тип шириной не менее # бит; существует на любой платформе, поэтому на том же DSP-процессоре `std::int_least8_t` окажется 16- или 32-битным, но код соберётся;
- `std::int_fast#_t` — самый *быстрый* тип шириной не менее # бит: разные процессоры эффективнее работают с разной шириной операндов.

Вместе они решают две проблемы типов фиксированной ширины — возможную потерю скорости и потерю переносимости. Насколько «не менее # бит» расходится с ожидаемым «ровно # бит», видно на любой машине:

> [!example] Сниппет 1.12 — `least` и `fast` на вашей платформе
> ```cpp
> #include <cstdint>
> #include <iostream>
>
> int main()
> {
>     std::cout << "int_least16_t = " << sizeof(std::int_least16_t) << '\n';
>     std::cout << "int_fast16_t  = " << sizeof(std::int_fast16_t)  << '\n';
>     std::cout << "int_least32_t = " << sizeof(std::int_least32_t) << '\n';
>     std::cout << "int_fast32_t  = " << sizeof(std::int_fast32_t)  << '\n';
> }
> ```
>
> Вывод на macOS (Apple clang):
>
> ```
> int_least16_t = 2
> int_fast16_t  = 2
> int_least32_t = 4
> int_fast32_t  = 4
> ```

### Самый широкий знаковый / беззнаковый целый тип

В том же заголовочном файле объявлена и пара имён на противоположный случай — когда нужен не минимальный, а максимально широкий тип.

> [!note] `std::intmax_t`, `std::uintmax_t`
> самый широкий знаковый (соответственно беззнаковый) целый тип, поддерживаемый реализацией: в него помещается значение любого другого целого типа этой реализации.

На платформах курса это 64 бита, то есть `sizeof intmax_t` равен 8 — причём даже у компиляторов, где есть 128-битное целое. Почему так и что это говорит о статусе такого 128-битного типа, разбирается ниже, в Примере 1.7.

> [!example] Сниппет 1.13 — Самый широкий целый тип реализации
> ```cpp
> #include <cstdint>    // std::intmax_t, std::uintmax_t
> #include <iostream>
> #include <limits>
>
> int main()
> {
>     std::cout << sizeof(std::intmax_t) << '\n';                        // 8 байт
>
>     // предельные значения самого широкого целого типа этой реализации
>     std::cout << std::numeric_limits<std::intmax_t>::max()  << '\n';   // 9223372036854775807
>     std::cout << std::numeric_limits<std::uintmax_t>::max() << '\n';   // 18446744073709551615
>
>     // значение любого целого типа помещается в intmax_t без потерь
>     long long big = std::numeric_limits<long long>::max();
>     std::intmax_t widest = big;
>     std::cout << (widest == big) << '\n';                              // 1 — значение сохранилось
> }
> ```

Именно это свойство — «вмещает любое целое значение реализации» — и делает `std::intmax_t` неудобным для компиляторов: объявить 128-битный тип полноценным расширенным целым значило бы расширить до 128 бит и `std::intmax_t`. О предельных значениях типов и о `std::numeric_limits` — в конце параграфа.

### Тип размера `std::size_t` и оператор `sizeof`

Когда в программе мы работаем с размерами, индексами элементов коллекций, то удобно использовать тип данных `std::size_t`.

> [!tip] Оператор `sizeof` возвращает значение типа `std::size_t`.
> Размер переменной / типа / объекта определяется во время компиляции (compile-time), поэтому `sizeof` можно использовать в константных выражениях.

> [!note] `std::size_t`
> беззнаковый целый тип, способный представить размер любого объекта в памяти данной платформы. Объявлен в заголовочном файле `<cstddef>` и др.

> [!example] Сниппет 1.14 — `std::size_t` для размеров и индексов
> ```cpp
> #include <cstddef>    // std::size_t
> #include <iostream>
> #include <iterator>   // std::size
> #include <string>
>
> int main()
> {
>     std::size_t doubleSize = sizeof(double);   // размер типа в байтах
>     std::cout << doubleSize << '\n';           // 8
>
>     int arr[]{1, 2, 3, 4, 5};
>     std::size_t count = std::size(arr);        // число элементов массива (C++17)
>     std::cout << count << '\n';                // 5
>
>     std::string str = "Hello, world!";
>     for (std::size_t i = 0; i < str.length(); ++i) {  // индекс — тоже размер, значит std::size_t
>         std::cout << str[i];
>     }
>     std::cout << '\n';                          // Hello, world!
> }
> ```

Метод `length()` возвращает как раз беззнаковый тип размера, поэтому счётчик цикла объявлен как `std::size_t`: заведи мы `int i`, компилятор с флагом `-Wall` предупредил бы о сравнении знакового с беззнаковым. Количество элементов массива здесь получено через `std::size` (C++17); как то же самое делали раньше, делением `sizeof(arr) / sizeof(arr[0])`, показано в §1.1.2.2 «Классификация типов данных C++». Не путайте два похожих имени: `std::size_t` — это **тип** из `<cstddef>`, а `std::size` — **функция**, возвращающая количество элементов. Объявлена она в `<iterator>` и, по требованию стандарта, в контейнерных заголовках — `<string>`, `<vector>`, `<array>` и других, — поэтому в сниппете строку с `<iterator>` можно было бы и опустить: `<string>` уже подключён. Оставлена она намеренно: для каждого используемого имени лучше подключать тот заголовочный файл, в котором оно объявлено, а не рассчитывать, что имя придёт попутно с каким-то другим заголовком (правило «подключайте заголовок для каждого средства, которым пользуетесь», см. §1.1.1.5 «Библиотеки и заголовочные файлы»).

> [!danger] `std::size_t` беззнаковый — и это ловушка
> Цикл в обратную сторону по индексам
>
> ```cpp
> for (std::size_t i = v.size() - 1; i >= 0; --i)   // никогда не завершится
> ```
>
> не заканчивается никогда: беззнаковое `i` не бывает отрицательным, поэтому условие `i >= 0` истинно всегда, а `--i` при нуле даёт не `-1`, а максимальное значение типа. Если же контейнер пуст, то `v.size() - 1` — это сразу максимальное значение, и первое же обращение `v[i]` выходит за границы. По той же причине сравнение `std::size_t` со знаковым `int` вызывает предупреждение компилятора (`-Wsign-compare`): перед сравнением `int` молча превращается в беззнаковый, и отрицательное значение становится огромным положительным.

> [!tip] Имена из `<cstdint>` и `<cstddef>` правильнее писать со `std::`
> Заголовочные файлы, имя которых начинается с `c` (`<cstdint>`, `<cstddef>`, `<cmath>`), — это библиотеки языка C, перенесённые в C++. Стандарт требует, чтобы объявленные в них имена находились в пространстве имён `std`, а попадут ли они ещё и в глобальное пространство имён — не определено. На практике попадают у всех распространённых компиляторов, поэтому запись без префикса — просто `int32_t` — обычно работает, но это удача реализации, а не гарантия стандарта.
>
> Переносимо и правильно: `std::int32_t`, `std::uint8_t`, `std::int_least8_t`, `std::size_t` — и `#include <cstdint>` либо `<cstddef>` (см. §1.1.4 «Пространство имён std. Using»). Заголовки в старом стиле `<stdint.h>` и `<stddef.h>` наоборот гарантируют имена в глобальном пространстве, но в C++ их использовать не принято.
>
> Если `std::` в каждом имени мешает читать код, имя вносят в текущую область видимости **using-объявлением** — и дальше пишут коротко:
>
> ```cpp
> #include <cstddef>
> using std::size_t;   // в область видимости попадает ровно одно имя
>
> size_t count = 0;
> ```

### Символьные типы

Символьные типы — это целочисленные типы, используемые для представления символов:

- `char` — основной символьный тип; всегда отдельный тип, хотя устроен как `signed char` или `unsigned char` — знаковость `char` зависит от платформы (на x86 обычно знаковый, на ARM — беззнаковый);
- `signed char` / `unsigned char` — знаковый и беззнаковый «маленькие целые»; `unsigned char` традиционно используется для представления «сырых» байтов;
- `char8_t` (C++20), `char16_t`, `char32_t` (C++11) — типы для кодовых единиц Юникода UTF-8/UTF-16/UTF-32;
- `wchar_t` — «широкий символ»; считается устаревшим: его размер различен (32 бита в Linux, 16 бит в Windows), что делает его непереносимым.

> [!tip] Расширенных символьных типов не бывает
> Все перечисленные символьные типы — стандартные и обязательные.
> Расширенные типы бывают у целых и, с C++23, у вещественных — см. раздел «Расширенные типы» ниже.

### Типы с плавающей точкой

Три типа для вещественных чисел различаются размером и точностью:

- `float` — 4 байта,
- `double` — 8 байт,
- `long double` — 16 или 8 байт в зависимости от платформы.

Основной «рабочий» тип — `double` (и литералы без «суффиксов» имеют именно этот тип — см. §1.1.2.3 «Литералы»).

У типов с плавающей точкой есть специальные значения `inf` (бесконечность) и `nan` («не число», *not a number*) — о них подробнее в теме 1.4 вместе с точностью вычислений и вводом-выводом.

> [!tip] Кроме стандартных вещественных бывают расширенные
> Кроме трёх стандартных типов C++23 описывает расширенные типы фиксированной ширины: `std::float16_t`, `std::float32_t`, `std::float64_t`, `std::float128_t`, `std::bfloat16_t` из заголовка `<stdfloat>`. Они необязательны — компилятор вправе их не предоставлять (например, Apple clang 21 не поставляет `<stdfloat>` вовсе). Детали — в разделе «Расширенные типы» ниже.

### Расширенные вещественные типы (C++23)

> [!abstract] Повышенный уровень: расширенные типы фиксированной ширины `<stdfloat>` (C++23)
> В C++23 появились ещё и **расширенные** типы фиксированной ширины — `std::float16_t`, `std::float32_t`, `std::float64_t`, `std::float128_t`, `std::bfloat16_t` из заголовка `<stdfloat>`. Имена этих типов приходят из стандартной библиотеки, но сами типы — фундаментальные типы языка; предоставлять их реализация не обязана — почему, разобрано сразу под этой выноской: например, Apple clang 21 заголовок `<stdfloat>` не поставляет вовсе.
> В задачах курса используйте `float`, `double`, `long double`; расширенные типы понадобятся там, где важны точная ширина представления и совместимость формата (графика, машинное обучение).

Здесь та же необязательность, но причина нагляднее — **аппаратура**. Форматы binary16, binary128 и bfloat16 поддерживаются процессором далеко не всегда. Сделать эти типы обязательными означало бы одно из двух:

- заставить компилятор эмулировать формат программно, что противоречит принципу «не платишь за то, чем не пользуешься»;
- либо объявить **неконформными** целые классы платформ — встраиваемые системы, сигнальные процессоры, — где такого формата нет и не будет.

Поэтому выбран третий путь: тип **необязателен, но если он есть — строго стандартизован**. Именно в этом отличие от расширенных целых.

**Таблица 1.2 — Расширенные целые и расширенные вещественные типы**

| Свойство | Расширенные целые | Расширенные вещественные (C++23) |
|---|---|---|
| Обязательны для реализации | нет | нет |
| Кто даёт имя | реализация (`__int128`) | стандарт (`std::float16_t`) |
| Представление в памяти | на усмотрение реализации | жёстко: форматы ISO/IEC 60559 |
| Переносимость кода | нулевая | полная, если тип вообще есть |

Получается, что C++23 не столько «добавил необязательные типы», сколько **навёл порядок в уже существующем «зоопарке»**: `_Float16` у GCC, `__fp16` у ARM, `__bf16`, `_Float128` — раньше каждый производитель называл и определял их по-своему, теперь имя и битовый формат зафиксированы стандартом.

Будет ли доступен `std::float16_t` и др., зависит от трёх составляющих:

- от версии стандарта,
- <!-- TODO: второй пункт списка на фото обрезан -->
- от целевой архитектуры процессора.

**GCC 13 и новее вместе с библиотекой libstdc++** — предложение `P1467R9` реализовано. Библиотека поставляет заголовок `<stdfloat>`, а компилятор для каждого доступного на этой платформе типа определяет свой макрос — `__STDCPP_FLOAT16_T__`, `__STDCPP_FLOAT32_T__` и так далее. Важный нюанс: имена из `<stdfloat>` — это псевдонимы встроенных расширенных типов компилятора (`_Float32`, `_Float64`), а не другие названия для `float` и `double`, поэтому `std::is_same_v<std::float32_t, float>` всегда даёт `false`.

**Clang вместе с библиотекой libc++** — заголовка `<stdfloat>` нет. Сам компилятор, начиная с версии 17, знает расширенные вещественные типы на уровне языка (`_Float16`, `__bf16`, литералы вида `0.0f16`), но стандартных имён `std::floatN_t` библиотека не предоставляет: соответствующая задача в LLVM до сих пор открыта. Например, Apple clang 21 на `#include <stdfloat>` отвечает `fatal error: 'stdfloat' file not found`.

**MSVC вместе с библиотекой Microsoft STL** — поддержки нет. Исторически в Windows `long double` совпадает с `double` (64 бита), а добавление 16- и 128-битных типов требует глубоких изменений в кодогенераторе, и работа остаётся в планах.

### Предельные значения типов

Минимальное и максимальное представимые значения любого **арифметического** типа (целые и вещественные типы) можно запросить через класс `std::numeric_limits` из заголовочного файла `<limits>`:

> [!example] Сниппет 1.15 — Предельные значения типов через `std::numeric_limits`
> ```cpp
> #include <iostream>
> #include <limits>
>
> int main()
> {
>     std::cout << "int:    [" << std::numeric_limits<int>::min() << ", "
>                              << std::numeric_limits<int>::max() << "]\n";
>
>     std::cout << "double: [" << std::numeric_limits<double>::lowest() << ", "
>                              << std::numeric_limits<double>::max() << "]\n";
> }
> ```
>
> Вывод на 64-битной платформе:
>
> ```
> int:    [-2147483648, 2147483647]
> double: [-1.79769e+308, 1.79769e+308]
> ```

> [!danger] У вещественных типов нижняя граница — это `lowest()`, а не `min()`
> Для целых типов `min()` — наименьшее значение диапазона, как и ожидается. А для `float`, `double` и `long double` `min()` возвращает наименьшее **положительное** нормализованное число: у `double` это примерно `2.22507e-308`, а вовсе не нижнюю границу диапазона. Нижняя граница — `lowest()` (появился в C++11); именно поэтому в сниппете для `double` взят он. Перепутать легко, а ошибка тихая: проверка «значение не меньше минимума», написанная с `min()`, отсечёт для вещественных все отрицательные значения.
