### Тип данных

Каждое значение, с которым работает программа, — число, символ, признак «истина/ложь» — принадлежит какому-то типу.

> [!note] Тип данных
> характеристика данных, определяющая множество допустимых значений данных, набор применимых к ним операций и объём памяти для хранения.

> [!tip]
> C++ — статически типизированный язык: тип каждого объекта известен уже на этапе компиляции и не меняется во время работы программы (см. §1.1.1.1 «Язык программирования»).

Типы данных C++ делятся на две большие группы.

1. **Фундаментальные** встроены в язык и готовы к использованию сразу: `int` — целые числа, `double` — вещественные, `char` — символы, `bool` — логические значения «истина/ложь».
2. **Пользовательские** программист определяет сам под свою задачу: структура `Point` с координатами точки, перечисление `Color` с набором цветов, классы — например, `std::string` из стандартной библиотеки. Эта тема посвящена фундаментальным типам; пользовательские подробно разбираются в разделе 2 (структуры) и во второй части курса (ООП).

> [!example] Пример 1.10 — Пользовательские типы «в работе»: вектор, точка, матрица
> Забегая вперёд — только чтобы почувствовать идею: программист описывает новый тип один раз, а дальше пользуется им так же свободно, как встроенным `int`.
>
> ```cpp
> #include <iostream>
> #include <vector>
>
> struct Point {      // пользовательский тип: точка на плоскости
>     double x{};
>     double y{};
> };
>
> struct Matrix {     // пользовательский тип: матрица произвольного размера
>     std::vector<std::vector<int>> data;  // вектор строк, каждая строка — вектор чисел
> };
>
> int main()
> {
>     std::vector<int> grades{9, 8, 10};  // вектор — динамический массив (стандартная библиотека)
>     grades.push_back(7);                // операция вектора: добавить элемент в конец
>     std::cout << grades.size() << '\n'; // 4 — текущее число элементов
>
>     Point p{3.0, 4.0};                  // точка с координатами (3; 4)
>     p.x = 5.0;                          // обращение к полю по имени
>     std::cout << p.x << '\n';           // 5
>
>     Matrix e{{{1, 0},
>               {0, 1}}};                 // единичная матрица 2×2
>     std::cout << e.data[0][0] + e.data[1][1] << '\n';  // 2 — след матрицы (сумма диагонали)
>
>     for (const auto& row : e.data) {       // цикл по строкам матрицы
>         for (const auto& value : row) {    // цикл по элементам строки
>             std::cout << value << ' ';
>         }
>         std::cout << '\n';                 // перевод строки после каждой строки матрицы
>     }                                       // напечатает: 1 0 / 0 1
> }
> ```

### Четыре фундаментальных типа

В C++ имеется набор из четырёх фундаментальных типов, отражающих характерные особенности организации памяти большинства компьютеров и наиболее распространённые способы хранения данных.

> [!note] Интегральные типы
> обобщённое название целочисленных типов данных. Стандарт относит к ним:
>
> - логический тип: `bool`;
> - символьные типы: `char`, `signed char`, `unsigned char`, `char8_t` (C++20), `char16_t`, `char32_t`, `wchar_t`;
> - знаковые целые типы: `signed char`, `short int`, `int`, `long int`, `long long int`;
> - беззнаковые целые типы: `unsigned char`, `unsigned short int`, `unsigned int`, `unsigned long int`, `unsigned long long int`.
>
> Типы `signed char` и `unsigned char` попадают сразу в две группы: они символьные и одновременно самые «узкие» целые — знаковый и беззнаковый.

> [!note] Типы с плавающей точкой
> типы для представления вещественных чисел: `float`, `double`, `long double`.

> [!note] void
> тип, используемый для указания на отсутствие информации.
> Например, как тип возвращаемого значения функции, которая ничего не возвращает.

> [!note] std::nullptr_t
> тип литерала нулевого указателя `nullptr`.
> Это отдельный, самостоятельный тип данных в C++ (C++11), который сам по себе не является указателем, используется специально для представления типа литерала `nullptr`.

Указателям и операциям над ними посвящён раздел в §1.1.2.2 «Классификация типов данных C++».

> [!abstract] Повышенный уровень
> Отметим, что `std::nullptr_t` — это базовый (фундаментальный) тип, такой же как `int` или `double`. Сам по себе он не указывает на какой-либо объект в памяти и не может быть разыменован. Его единственное назначение — гарантировать, что `nullptr` имеет строго определённый тип, отличный от целочисленных типов (в отличие от старого макроса `NULL`, который обычно равен `0`).
>
> Благодаря правилам языка, значение типа `std::nullptr_t` (то есть сам `nullptr`) может неявно преобразовываться в:
>
> - любой тип указателя на объект (`int*`, `MyClass*` и т. д.);
> - любой тип указателя на функцию;
> - любой тип указателя на член класса;
> - булево значение `bool` (преобразуется в `false`).
>
> Введение отдельного типа литерала нулевого указателя понадобилось для разрешения неоднозначности и исправления проблем с перегрузкой функций (overloading).

> [!example] Пример 1.11 — Перегрузка функции для числа и для указателя
> ```cpp
> #include <iostream>
>
> void foo(int x)    { std::cout << "Вызвана функция для int\n"; }
> void foo(int* ptr) { std::cout << "Вызвана функция для указателя\n"; }
>
> int main()
> {
>     foo(0);         // вызовет foo(int): 0 — это int
>     // foo(NULL);   // неоднозначность: NULL обычно раскрывается в 0
>
>     foo(nullptr);   // однозначно вызовет foo(int*): std::nullptr_t
>                      // не приводится к int, но приводится к указателю
> }
> ```

### Логический тип

> [!note] Логический тип bool
> тип для представления истинности: имеет ровно два значения — `true` (истина) и `false` (ложь).

Тип `bool` — самый простой из фундаментальных: множество его значений состоит всего из двух элементов. Значение типа `bool` получается как результат сравнения (`a < b`) и логических операций (`&&`, `||`, `!`) — именно его проверяют условный оператор `if` и циклы (тема 1.2).

При преобразовании в целое `true` даёт `1`, а `false` — `0`; в обратную сторону ноль превращается в `false`, а любое ненулевое значение — в `true`.

Размер `bool` стандарт не фиксирует, на практике это 1 байт: меньше одного байта адресовать нельзя, хотя для самих значений хватило бы одного бита.

Хранится `bool` как целое число, поэтому в классификации выше он попадает в первую из четырёх групп — интегральные типы.

> [!abstract] Повышенный уровень: `std::vector<bool>` — особый случай
> У вектора (см. Пример 1.10) для `bool` сделана отдельная реализация: вместо байта на элемент он хранит по одному биту, экономя память примерно в восемь раз. Плата за это — элемент такого вектора перестаёт быть обычным объектом `bool`: у отдельного бита нет собственного адреса, поэтому `v[i]` возвращает не ссылку `bool&`, а вспомогательный объект-посредник, который умеет читать и записывать нужный бит.
>
> Отсюда три неожиданности, которых нет ни у какого другого `std::vector`:
>
> - `bool& b = v[0];` не компилируется — привязать ссылку не к чему;
> - `auto x = v[0];` даёт посредника, а не копию значения, и присваивание `x = true;` меняет сам вектор;
> - у `std::vector<bool>` нет метода `data()` — непрерывного массива `bool` внутри просто не существует.
>
> Поэтому `std::vector<bool>` считают неудачным решением стандартной библиотеки. Если нужен обычный контейнер логических значений — берут `std::vector<char>`; если количество флагов известно заранее — `std::bitset`. Подробно контейнеры разбираются в разделе 2.

### Целочисленные типы

Существует пять стандартных знаковых целочисленных типов: `signed char`, `short int`, `int`, `long int`, `long long int` — в этом списке каждый тип предоставляет как минимум столько же памяти, сколько предыдущие. Диапазон представимых значений знакового типа шириной N бит — от −2^(N−1) до 2^(N−1) − 1 включительно; почему диапазон именно таков и отчего он несимметричен, объясняет способ кодирования отрицательных чисел — дополнительный код (см. §1.4.2.1 «Представление целых чисел — прямой, обратный и дополнительный код»).

> [!note] sizeof
> оператор, возвращающий размер типа или объекта в байтах.

Например, `sizeof(int)` на большинстве современных платформ равен 4.

Реальные размеры зависят от платформы (это поведение, определяемое реализацией, — см. §1.1.2.6 «Константность переменных (`const`, `constexpr`)»):

**Таблица 1.3 — Размеры некоторых типов данных**

| Тип | Минимум по стандарту, бит | 64-битная Windows (LLP64) | 64-битные Linux/macOS (LP64) |
|---|---|---|---|
| `signed char` | 8 | 8 | 8 |
| `short int` | 16 | 16 | 16 |
| `int` | 16 | 32 | 32 |
| `long int` | 32 | 32 | 64 |
| `long long int` | 64 | 64 | 64 |

Обратите внимание на строку `long` — на Windows и Linux этот тип имеет разный размер; полная таблица моделей данных — по ссылке в документации.

> Между таблицей 1.3 и следующим фрагментом на фото пропущен кусок текста (судя по всему — про **расширенные целые типы**, которые компилятор может предлагать сверх стандартных, например `__int128` у GCC/Clang, и о том, почему полагаться на них в переносимом коде нельзя). Дозаписать со следующих снимков.

…использовать нельзя: программа не соберётся на Windows с MSVC и в 32-битных сборках. Если нужна разрядность больше 64 бит, берут библиотеку «длинной арифметики» или реализуют её сами, см. §1.1.2.1 (доп.) «C++. Библиотеки длинной арифметики».

Расширенные типы важно отличать от **типов фиксированной ширины** из `<cstdint>` — это имена-синонимы (`typedef`) для тех же стандартных типов, что уже есть у процессора. Заголовок `<cstdint>` обязателен с C++11, поэтому на любом современном компиляторе эти имена доступны.

Имена устроены единообразно: `int8_t`/`uint8_t`, `int16_t`/`uint16_t`, `int32_t`/`uint32_t`, `int64_t`/`uint64_t` — число означает ширину в битах, префикс `u` — беззнаковость. Если платформа такого типа не поддерживает, программа с ним не скомпилируется.

Согласно стандарту C++ (и C), типы заданной точности `int8_t`, `int16_t`, `int32_t` и `int64_t` являются **опциональными**. Они гарантированно существуют в заголовочном файле `<cstdint>` (`<stdint.h>`) только в том случае, если аппаратная архитектура нативно поддерживает знаковые целые типы именно такой разрядности (8, 16, 32, 64 бит), использующие двоичный дополнительный код (two's complement) и не имеющие заполняющих битов (padding bits), см. §1.4.2.1 «Представление целых чисел — прямой, обратный и дополнительный код».

> [!tip] Дополнено (по учебнику Страуструпа, §1.4)
> Каждый фундаментальный тип напрямую соответствует аппаратному представлению и имеет фиксированный размер, определяющий диапазон хранимых значений; переменная типа `char` рассчитана на естественный размер символа на данной машине (обычно 8 бит), а размеры остальных типов кратны размеру `char`. Когда важна не удобная запись, а гарантированный размер — используют псевдонимы из `<cstdint>`, как описано выше.
