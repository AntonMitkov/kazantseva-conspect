### Цепочка if — else if — else

Если вариантов больше двух, инструкции `if` соединяют в цепочку: ветвь `else` одной инструкции сама является инструкцией `if`.

> [!example] Сниппет 1.36 — Цепочка if — else if — else
> ```cpp
> if (условие1) {
>     // …
> } else if (условие2) {
>     // …
> } else if (условие3) {
>     // …
> } else {
>     // …
> }
> ```

```cpp
#include <iostream>

int signOf(int value)
{
    int sign = 0;
    if (value < 0) {
        sign = -1;
    } else if (value > 0) {
        sign = 1;
    }
    return sign;
}

int main()
{
    int number = 0;
    std::cin >> number;
    std::cout << signOf(number) << '\n';
}
```

### Условие: частные случаи

**Проверка на «не ноль».** Записи `if (x)` и `if (x != 0)` для целого `x` равносильны: в первой число неявно преобразуется в `bool`. Для числовых переменных явное сравнение `x != 0` читается лучше: оно сообщает, что `x` — число, а не логическое значение.

**Логическая переменная как флаг.** Переменную типа `bool`, которая хранит признак «событие произошло» или «условие выполнено», называют **флагом** (flag). Её имя начинается с `is`, `has`, `can` или `should` (пункт 4о 0.8 «Основы Code Style»), и в условии её пишут без сравнения: `if (hasOdd)`, а не `if (hasOdd == true)`; отрицание — `if (!hasOdd)`.

### Инициализация в заголовке if (C++17)

С C++17 перед условием можно поместить **инициализирующую инструкцию** (init-statement) — объявление переменной, которая нужна только для проверки и обработки её результата:

```
if (инициализация; условие) {
    // ветвь для истинного условия
} else {
    // ветвь для ложного условия
}
```

Такая запись равносильна следующей:

```
{
    инициализация;
    if (условие) {
        // …
    } else {
        // …
    }
}
```

> [!example] Пример 1.40 — Чтение числа с проверкой в заголовке if
> ```cpp
> #include <iostream>
>
> int main()
> {
>     if (int value = 0; std::cin >> value) {
>         std::cout << "прочитано число " << value << '\n';
>     } else {
>         std::cout << "ввод не является числом\n";
>     }
>     // value здесь уже не видна
> }
> ```

Выражение `std::cin >> value` в условии преобразуется в `true`, если число прочитано, и в `false`, если ввод не является числом. Для ввода `7` программа выводит `прочитано число 7`, для `abc` — `ввод не является числом`.

Тот же приём применяют к файлам: объект файлового потока создаётся и проверяется в заголовке `if` и недоступен после него. Работа с файлами рассматривается в теме 2.5.

> [!example] Пример 1.41 — Открытие файла в заголовке if
> ```cpp
> #include <fstream>
> #include <iostream>
> #include <string>
>
> int main()
> {
>     if (std::ifstream file("data.txt"); file.is_open()) {
>         std::string line;
>         while (std::getline(file, line)) {
>             std::cout << line << '\n';
>         }
>     } else {
>         std::cerr << "не удалось открыть файл\n";
>     }
>     // file здесь уже не виден
> }
> ```

### Вложенные инструкции if

Ветвь инструкции `if` может содержать другую инструкцию `if`. Вложение ухудшает наглядность даже при правильном форматировании:

```cpp
int maxOfThree(int a, int b, int c)
{
    int maxValue = 0;
    if (a > b) {
        if (a > c) {
            maxValue = a;
        } else {
            maxValue = c;
        }
    } else if (b > c) {
        maxValue = b;
    } else {
        maxValue = c;
    }
    return maxValue;
}
```

> [!warning] Ловушка: «висячий» `else`
> Без фигурных скобок ветвь `else` относится к ближайшей инструкции `if`, а не к той, под которой она выровнена отступом:
>
> ```cpp
> if (a > 0)
>     if (b > 0)
>         std::cout << "оба числа положительны\n";
> else
>     std::cout << "a не положительно\n";
> ```
>
> Отступ подсказывает, что `else` относится к `if (a > 0)`, но компилятор связывает его с `if (b > 0)`. При `a = 1`, `b = -1` программа выводит `a не положительно`, а при `a = -1` не выводит ничего. Эта ошибка называется **висячим `else`** (dangling else). Clang при `-Wall` предупреждает: `add explicit braces to avoid dangling else [-Wdangling-else]`. Фигурные скобки вокруг каждой ветви исключают её полностью.

### `if constexpr` и `if consteval`

<!-- TODO: начало раздела про if constexpr (пример с проверкой sizeof(long)) на фото не попало; виден только конец примера: -->

```cpp
        std::cout << "long уже, чем long long\n";
    }
}
```

Основное применение `if constexpr` — шаблоны функций, где ветвь выбирается в зависимости от типа параметра (тема 2.3).

Инструкция `if consteval` используется внутри `constexpr`-функции и выбирает ветвь в зависимости от того, где функция вычисляется: при компиляции или при выполнении программы.

```cpp
#include <iostream>

constexpr const char* whereComputed()
{
    if consteval {
        return "при компиляции";
    } else {
        return "при выполнении";
    }
}

int main()
{
    constexpr const char* COMPILE_RESULT = whereComputed();
    const char* runtimeResult = whereComputed();
    std::cout << COMPILE_RESULT << '\n' << runtimeResult << '\n';
}
```

## 1.2.5.2 Инструкция switch: мультиветвление

> [!quote] Документация и стандарт по теме
> **Документация:**
> - Инструкция `switch`: <https://cppreference.com/cpp/language/switch>
> - Инструкция `break`: <https://cppreference.com/cpp/language/break>
> - Атрибут `[[fallthrough]]`: <https://cppreference.com/cpp/language/attributes/fallthrough>
>
> **Стандарт:**
> - Инструкция `switch`: <https://eel.is/c++draft/stmt.switch>
> - Инструкция `break`: <https://eel.is/c++draft/stmt.break>
> - Атрибут `[[fallthrough]]`: <https://eel.is/c++draft/dcl.attr.fallthrough>

Цепочка `if — else if` (см. [[#1.2.5.1 Инструкции выбора (if, if-else, вложенные if)|1.2.5.1]]) проверяет условия по очереди. Когда нужно выбрать ветвь по значению одного целого выражения из списка известных заранее значений, удобнее инструкция `switch`: все варианты перечислены в одном месте.

> [!abstract] Инструкция `switch` (switch statement)
> инструкция выбора, которая передаёт управление одной из ветвей, помеченных метками `case`, в зависимости от значения условия; если ни одна метка не подошла — ветви `default`.
>
> ```
> switch (условие) {
> case константное-выражение-1: инструкции
> case константное-выражение-2: инструкции
> default: инструкции
> }
>
> switch (инициализация; условие)
>     инструкция
> ```

### Условие и метки case

Условие инструкции `switch` должно иметь:

- целочисленный тип, в том числе `char` и `bool` (см. [[lekciya-04|1.1.2.1 Фундаментальные типы данных C++]]);
- тип перечисления (см. [[lekciya-06|1.1.2.6.1 Перечисление (enum)]]);
- тип класса, который неявно преобразуется в целочисленный тип или в перечисление (раздел 4).

Вещественные числа и строки условием `switch` быть не могут: выбор по строке записывают цепочкой `if — else if` (см. функцию `parseCommand` в Примере 1.48).

Значение в метке `case` — **константное выражение** (constant expression), то есть значение, известное при компиляции: литерал, `constexpr`-константа или значение перечисления (см. [[lekciya-08#1.1.2.5 Константность переменных (const, constexpr)|1.1.2.5 Константность переменных]]). Значения меток не могут повторяться; для двух меток `case 'a':` Clang сообщает `error: duplicate case value '97'` — в сообщении код символа `'a'`.

### Выполнение switch и инструкция break

Инструкция `switch` вычисляет условие и переходит к метке `case` с совпадающим значением, а если такой нет — к метке `default`. Дальше инструкции выполняются подряд, пока не встретится инструкция `break` или конец `switch`: метки `case` только отмечают точки входа, но не ограничивают ветвь.

> [!abstract] Инструкция `break` (break statement)
> инструкция перехода, которая прерывает выполнение ближайшего охватывающего цикла (`for`, `for` по диапазону, `while`, `do-while`) или инструкции `switch`; управление передаётся инструкции, следующей за ними.
>
> ```
> break;
> ```

Поэтому каждая ветвь `switch` обычно заканчивается инструкцией `break`. Использование `break` в циклах рассматривается в 1.2.6 «Инструкции циклов» и 1.2.7 «Инструкции перехода».

> [!example] Сниппет 1.37 — Инструкция switch с break и default
> ```cpp
> switch (выражение) {
> case значение1:
>     // действия для значения1
>     break;
> case значение2:
> case значение3:
>     // общие действия для значений 2 и 3
>     break;
> default:
>     // недопустимое значение
>     break;
> }
> ```

### Проваливание и атрибут `[[fallthrough]]`

Если ветвь не заканчивается инструкцией `break`, выполнение продолжается в следующей ветви. Такое продолжение называется **проваливанием** (fallthrough). Обычно проваливание — ошибка: забытый `break`. Clang с флагом `-Wimplicit-fallthrough` предупреждает о нём:

```
warning: unannotated fall-through between switch labels [-Wimplicit-fallthrough]
```

Если проваливание задумано, его помечают атрибутом `[[fallthrough]];` (C++17) в конце ветви: читатель видит, что `break` пропущен намеренно, и компилятор не предупреждает.

> [!warning] Ловушка: объявление переменной внутри case
> Метки `case` — точки входа в один общий блок `switch`. Переменная, объявленная в одной ветви, видна и в следующих, но переход к следующей метке обходил бы её инициализацию, поэтому такой код не компилируется:
>
> ```cpp
> switch (code) {
> case 0:
>     int count = 1;      // ошибка компиляции
>     return count;
> case 1:
>     return 2;
> }
> ```
>
> Clang сообщает `error: cannot jump from switch statement to this case label` и поясняет: `note: jump bypasses variable initialization`. Если ветви нужна своя переменная, ветвь заключают в фигурные скобки: `case 0: { int count = 1; return count; }` — переменная видна только внутри этого блока (см. 1.2.4 «Составная инструкция»).

>             return "зелёный";
>         case Colour::BLUE:
>             return "синий";
>         default:
>             return "неизвестный цвет";
>     }
> }
>
> int main()
> {
>     std::cout << colourName(0) << '\n' << colourName(2) << '\n' << colourName(5) << '\n';
> }

> [!question]- Можно ли использовать строку `std::string` в качестве условия `switch`?
> Нет. Условие `switch` должно быть целого типа, перечислением или классом, преобразуемым в них. Выбор по строке записывают цепочкой `if — else if` или сначала переводят строку в значение перечисления.

> [!question]- Почему не компилируется ветвь `case 0: int count = 1; return count;`, за которой следует `case 1:`?
> Переход к метке `case 1` обходил бы инициализацию переменной `count`, которая видна во всём блоке `switch`. Переменную ветви объявляют внутри фигурных скобок: `case 0: { int count = 1; return count; }`.

Инструкция `if-else` выбирает, какое **действие** выполнить. Когда же нужно выбрать одно из двух **значений**, используют условный оператор: он является выражением (см. [[lekciya-09#1.2.3.2 Выражения|1.2.3.2 Выражения]]), поэтому его результат можно присвоить переменной, передать в функцию или вывести.

> [!abstract] Условный (тернарный) оператор (conditional operator)
> оператор `?:` с тремя операндами — `условие ? выражение1 : выражение2`: вычисляется условие; если оно равно `true`, вычисляется `выражение1` и его значение становится значением всего выражения, иначе вычисляется `выражение2`.

Название «тернарный» (ternary) указывает на число операндов: `?:` — единственный оператор C++ с тремя операндами (см. [[lekciya-09#1.2.3.3 Операторы языка C++|1.2.3.3 Операторы языка C++]]). Из двух выражений после условия вычисляется только одно. Поэтому условный оператор, как и логический оператор `&&` (см. [[lekciya-10#1.2.3.3.5 Логические операторы|1.2.3.3.5 Логические операторы]]), защищает от вычисления, которое недопустимо при ложном условии:

```cpp
const double ratio = count != 0 ? static_cast<double>(total) / count : 0.0;
```

При `count == 0` деление не выполняется, и `ratio` получает значение `0.0`.

> [!example] Сниппет 1.38 — Выбор из двух значений
> ```cpp
> int minOf2(int first, int second)
> {
>     return first < second ? first : second;   // значение возвращается из функции
> }
>
> int minValue = a < b ? a : b;                     // значение инициализирует переменную
> int minValue2 = a * (a < b) + b * (a >= b);       // TODO: комментарий на фото не попал
>
> std::cout << (isAdmin ? "администратор" : "пользователь") << '\n';   // значение передаётся в вывод
> ```

Условный оператор выбирает значение, которое возвращается из функции, инициализирует переменную или передаётся в вывод. В выводе условный оператор заключают в скобки (см. ловушку ниже).

> [!example] Сниппет 1.39 — Константа, значение которой зависит от условия
> ```cpp
> const int limit;            // ошибка: константа без инициализатора
> if (n > 10) {
>     limit = 5;              // ошибка: присваивание константе
> } else {
>     limit = 7;              // ошибка: присваивание константе
> }
>
> const int limit = n > 10 ? 5 : 7;   // корректно
> ```

Константа получает значение только при инициализации, в момент объявления: объявить её без значения и присвоить значение позже нельзя (см. [[lekciya-08#1.1.2.5 Константность переменных (const, constexpr)|1.1.2.5 Константность переменных]]). Инструкция `if-else` выбирает действие, а не значение, поэтому инициализировать константу в зависимости от условия она не может. Для первого фрагмента Clang сообщает:

```
error: default initialization of an object of const type 'const int'
error: cannot assign to variable 'limit' with const-qualified type
```

> [!example] Пример 1.49 — Четыре записи выбора наименьшего числа
> ```cpp
> // 1. инструкция if-else
> int minValue1 = 0;
> if (a < b) {
>     minValue1 = a;
> } else {
>     minValue1 = b;
> }
>
> // 2. инициализация и if без else
> int minValue2 = b;
> if (a < b) {
>     minValue2 = a;
> }
>
> // 3. условный оператор выбирает значение
> const int minValue3 = a < b ? a : b;
>
> // 4. условный оператор выбирает присваивание
> int minValue4 = 0;
> a < b ? minValue4 = a : minValue4 = b;
> ```
>
> Все четыре записи дают одинаковый результат. <!-- TODO: продолжение пояснения на фото обрезано --> …зависит от грамматики языка: в C++ третьим операндом может быть присваивание, а в языке C та же строка не компилируется (`expression is not assignable`).

> [!danger] Правило — `?:` выбирает значение, `if` выбирает действие
> Условный оператор используют, когда из двух значений нужно выбрать одно, — для инициализации, возврата из функции, аргумента функции. Если в ветвях выполняются действия (присваивания, вывод, вызовы функций ради побочного эффекта), пишут инструкцию `if-else`.

Приоритет условного оператора ниже, чем у арифметических операторов, операторов сравнения и логических операторов, поэтому в записи `a < b ? a : b` скобки вокруг условия не нужны (см. 1.2.3.4 «Приоритет, ассоциативность и порядок вычисления операций»). Но он ниже и приоритета оператора `<<`, которым выполняется вывод в поток.

> [!warning] Ловушка: условный оператор в выводе без скобок
> Запись `std::cout << a < b ? a : b;` компилятор разбирает как `((std::cout << a) < b) ? a : b`: сначала выводится `a`, затем поток сравнивается с числом. Clang сообщает об ошибке:
>
> ```
> error: invalid operands to binary expression ('ostream' and 'int')
> ```
>
> Условный оператор в выводе всегда заключают в скобки: `std::cout << (a < b ? a : b);`.

### Результат условного оператора

Тип и категория значения результата зависят от двух последних операндов:

- **одинаковый тип, оба операнда — lvalue**: результат — тоже lvalue этого типа, то есть сам выбранный объект, и ему можно присвоить значение;
- **разные арифметические типы**: операнды приводятся к общему типу по обычным арифметическим преобразованиям (см. 1.2.3.5 «Преобразования типов и возможные проблемы»), и результат — временное значение (rvalue, см. [[lekciya-09#1.2.3.2 Выражения|1.2.3.2 Выражения]]) общего типа. Как и при сравнении (см. [[lekciya-10#1.2.3.3.4 Операторы сравнения|1.2.3.3.4 Операторы сравнения]]), преобразоваться может любой из операндов, причём независимо от того, какой из них будет выбран;
- **общего типа нет**: ошибка компиляции.

> [!example] Пример 1.50 — Результат условного оператора: lvalue и общий тип

> int m = 10;
> (n == m ? n : m) = 7;   // n != m, поэтому m = 7
> std::cout << "n = " << n << ", m = " << m << '\n';
>
> int count = 3;
> std::cout << (count > 0 ? count : 0.5) / 2 << '\n';
