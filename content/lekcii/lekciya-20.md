### 3.3.5.1 Объявление и вызов указателя на функцию

> [!info] Свойства заметки
> Тип: параграф учебника · статус: черновик · дата обновления: 04.11.2026 · предпосылки: [[lekciya-06|1.1.2.6.4 Указатель]].

> [!quote] Документация и стандарт по теме
> - Указатели на функции: https://cppreference.com/cpp/language/pointer
> - Стандарт, функции и их типы: https://eel.is/c++draft/dcl.fct

Указатель может хранить не только адрес объекта, но и адрес функции.

> [!abstract] Указатель на функцию (function pointer)
> указатель, который хранит адрес функции; через него функцию можно вызвать.

Имя функции в выражении неявно преобразуется в указатель на эту функцию — так же, как имя массива в указатель на первый элемент. Поэтому указателю можно присвоить просто имя функции: `functionPointer = printHello;` равносильно `functionPointer = &printHello;`. Такая переменная объявляется следующим образом:

```cpp
returnType (*functionPointer)(args);
```

где `returnType` — тип возвращаемого функцией значения, `functionPointer` — имя указателя, `args` — типы параметров через запятую, если параметры есть.

Например, определим указатель на функцию:

```cpp
void (*functionPointer)() = nullptr;
```

Определён указатель с именем `functionPointer`. Он может указывать на функции без параметров с возвращаемым типом `void`. Вызов через нулевой указатель на функцию — неопределённое поведение; если указатель может быть пустым, его проверяют: `if (functionPointer) { functionPointer(); }`.

> [!example] Пример — Вызов функций через указатель на функцию
> Вывести приветствие и прощание, вызывая обе функции через один указатель.
> ```cpp
> #include <iostream>
>
> void printHello()
> {
>     std::cout << "Hello, World\n";
> }
>
> void printGoodbye()
> {
>     std::cout << "Good Bye, World\n";
> }
>
> int main()
> {
>     void (*functionPointer)() = printHello;
>     functionPointer(); // то же, что printHello()
>     functionPointer = printGoodbye;
>     functionPointer(); // то же, что printGoodbye()
>     return 0;
> }
> ```

Указателю можно присвоить имя функции, которая соответствует ему по возвращаемому типу и типам параметров: после `functionPointer = printHello;` указатель хранит адрес функции `printHello`. Вызвать её можно обращением к указателю: `functionPointer();`, либо с явным разыменованием: `(*functionPointer)();`. Впоследствии указателю можно присвоить адрес другой функции.

> [!warning] Ловушка: скобки вокруг имени указателя
> Определение `void (*functionPointer)();` не равносильно записи `void* functionPointer();`. Во втором случае объявлен не указатель на функцию, а функция `functionPointer`, которая возвращает указатель типа `void*`.

> [!example] Пример — Функции для вычисления арифметических выражений
> Вычислить сумму и разность двух чисел, вызывая обе функции через один указатель.
> ```cpp
> #include <iostream>
>
> int add(int x, int y)
> {
>     return x + y;
> }

### 3.3.5.2 Массивы указателей на функции

> [!quote] Документация и стандарт по теме
> - Указатели на функции: https://cppreference.com/cpp/language/pointer
> - Стандарт, объявления массивов: https://eel.is/c++draft/dcl.array
> - Стандарт, функции и их типы: https://eel.is/c++draft/dcl.fct

Кроме одиночных указателей на функции можно определять их массивы:

```cpp
returnType (*actions[size])(args);
```

Например, в записи `double (*actions[2])(int, int);` имя `actions` обозначает массив из двух указателей на функции, каждая из которых принимает два параметра типа `int` и возвращает значение типа `double`.

> [!example] Пример — Массив указателей на функции
> ```cpp
> // TODO: код примера (функции add, subtract, multiply и массив operations) на фото не попал
> ```
> Вывод программы:
> ```
> 15
> 5
> 50
> ```
> Массив `operations` содержит указатели на три функции, которые по очереди вызываются в цикле.

Все функции в массиве должны иметь одну и ту же сигнатуру: тип указателя включает и возвращаемый тип, и типы параметров. Запись массива упрощает псевдоним типа (3.3.5.4): `using Operation = int (*)(int, int);` и затем `Operation operations[] = {add, subtract, multiply};`.

> [!summary] Резюме
> - Массив указателей на функции объявляют как `returnType (*name[size])(args);` все функции в нём имеют одинаковую сигнатуру, их выбирают индексом или перебирают циклом.

Без него для сортировки одного массива по убыванию, а другого по возрастанию потребовалось бы несколько версий функции сортировки. Тот же приём используют стандартные алгоритмы: `std::ranges::sort(values, std::greater{})` сортирует по убыванию (3.2.8 «Библиотека алгоритмов»). ```cpp
void selectionSort(int* values, int size, bool shouldReplace(int, int));
```

### 3.3.5.4 Указатель на функцию и псевдонимы типов

> [!quote] Документация и стандарт по теме
> - Псевдонимы типов: https://cppreference.com/cpp/language/type_alias
> - Стандарт, объявление псевдонима: https://eel.is/c++draft/dcl.typedef

Запись типа указателя на функцию можно сократить псевдонимом (см. [[lekciya-16#1.6.3 Ключевое слово using|1.6.3 Ключевое слово using]]). Новое имя стоит слева от знака `=`, а тип указателя записывается без имени:

```cpp
using ValidateFunctionPointer = bool (*)(int, int);
```

Псевдоним `ValidateFunctionPointer` обозначает указатель на функцию, которая принимает два значения типа `int` и возвращает логическое значение. Теперь вместо объявления

```cpp
bool validate(int x, int y, bool (*validator)(int, int));
```

можно записать:

```cpp
bool validate(int x, int y, ValidateFunctionPointer validator);
```

То же можно записать с `typedef` — `typedef bool (*ValidateFunctionPointer)(int, int);`, — но запись с `using` читается легче: имя стоит слева, как в обычном присваивании (см. 1.6.3); кроме того, только `using` позволяет объявить шаблон псевдонима ([[lekciya-19#3.4.2.9 Шаблон псевдонима|3.4.2.10 Шаблон псевдонима]]).

Псевдоним можно ввести и для самого *типа функции*, без указателя; тогда звёздочка остаётся видна в объявлении параметра:

```cpp
using Validator = bool(int, int);                       // тип функции

bool validate(int x, int y, Validator* validator);      // параметр — указатель на функцию
```

> [!summary] Резюме
> - Синтаксис объявления указателя на функцию сложен и подвержен ошибкам; его упрощают псевдонимом типа `using`. <!-- TODO: остальные пункты резюме на фото не попали -->

### 3.3.5.5 Обёртка `std::function`

> [!quote] Документация и стандарт по теме
> - `std::function`: https://cppreference.com/cpp/utility/functional/function · стандарт: https://eel.is/c++draft/func.wrap.func
> - `std::ref`, `std::cref`: https://cppreference.com/cpp/utility/functional/ref · `std::reference_wrapper` в стандарте: https://eel.is/c++draft/refwrap

Вместо указателя на функцию можно использовать шаблон класса `std::function` из заголовочного файла `<functional>` (с C++11). Это не указатель, а полиморфная обёртка общего назначения: объект `std::function` может хранить, копировать и вызывать любой вызываемый объект — функцию, лямбда-выражение (см. 3.2.8 «Библиотека алгоритмов») или объект-функцию.

Аргумент шаблона — тип функции: `std::function<bool(int, int)>` хранит вызываемые объекты, которые принимают два `int` и возвращают `bool`. Если параметров нет, круглые скобки оставляют пустыми: `std::function<void()>`.

> [!example] Пример — Функция с параметром `std::function`
> Проверить пару чисел функцией, которую выбирает вызывающий код: обычной функцией и лямбда-выражением.
> ```cpp
> #include <functional>
> #include <iostream>
>
> bool validate(int x, int y, const std::function<bool(int, int)>& validator)
> {
>     return validator(x, y);
> }
>
> bool isLess(int x, int y)
> {
>     return x < y;
> }
>
> int main()
> {
>     std::cout << validate(1, 2, isLess) << '\n'; // 1
>     std::cout << validate(1, 2, [](int x, int y) { return x == y; }) << '\n'; // 0
>     return 0;
> }
> ```

Объект `std::function`, созданный по умолчанию или из `nullptr`, пуст. Вызов пустого `std::function` выбрасывает исключение `std::bad_function_call` (тема 3.7) — в отличие от указателя на функцию, вызов которого через `nullptr` даёт неопределённое поведение. Проверить, хранит ли объект что-нибудь, можно так же, как указатель: `if (validator) { … }`.

Запись длиннее, чем у указателя на функцию, но возвращаемый тип и параметры в ней видны явно. Для `std::function` тоже можно ввести псевдоним:

```cpp
#include <functional>

using ValidateFunctionPointer = bool (*)(int, int);       // псевдоним указателя на функцию
using ValidateFunction = std::function<bool(int, int)>;  // псевдоним std::function
```

`std::function` хранит копию вызываемого объекта. Пока объект ничего не хранит, как функция `isLess`, это незаметно. Но замыкание может хранить состояние, и тогда вызовы через `std::function` меняют копию, а не исходный объект. Чтобы `std::function` хранил ссылку на объект, при инициализации объект оборачивают функцией `std::ref` из `<functional>` (см. 3.3.1.1 «Любая операция над ссылкой — операция над объектом»).

> [!example] Пример — `std::function` хранит копию или ссылку
> Сравнить, как меняется состояние замыкания при вызовах через копию и через ссылку.
> ```cpp
> #include <functional>
> #include <iostream>
>
> int main()
> {
>     int calls = 0;
>     auto counter = [calls]() mutable { return ++calls; }; // замыкание хранит свою копию calls
>
>     std::function<int()> byCopy = counter;          // хранит копию counter
>     std::function<int()> byRef = std::ref(counter); // хранит ссылку на counter
>
>     byCopy();
>     byCopy();
>     std::cout << counter() << '\n'; // 1: вызовы через byCopy изменили копию
>     byRef();
>     std::cout << counter() << '\n'; // 3: вызов через byRef изменил сам counter
>     std::cout << calls << '\n';     // 0: локальная переменная calls не менялась
>     return 0;
> }
> ```

### 3.3.5.6 Вывод типа указателя на функцию

> [!quote] Документация и стандарт по теме
> - Спецификатор `auto`: https://cppreference.com/cpp/language/auto · стандарт: https://eel.is/c++draft/dcl.spec.auto

Спецификатор `auto` может определять и тип указателя на функцию:

> [!example] Пример — `auto` для указателя на функцию
> Сохранить адрес функции в переменной, не записывая тип указателя.
> ```cpp
> #include <iostream>
>
> int getDouble(int value)
> {
>     return value * 2;
> }
>
> int main()
> {
>     const auto functionPointer = &getDouble;
>     std::cout << functionPointer(2) << '\n'; // 4
>     return 0;
> }
> ```
> Знак `&` здесь не обязателен: `auto p = getDouble;` даёт тот же тип, потому что имя функции неявно преобразуется в указатель. `const` делает константным сам указатель: тип `functionPointer` — `int (* const)(int)`, и присвоить ему адрес другой функции нельзя.

### 3.3.6.1 Автоматическая и динамическая память

> [!quote] Документация и стандарт по теме
> - Длительность хранения: https://cppreference.com/cpp/language/storage_duration
> - Выражение `new`: https://cppreference.com/cpp/language/new
> - Выражение `delete`: https://cppreference.com/cpp/language/delete
> - Стандарт, динамическая длительность хранения: https://eel.is/c++draft/basic.stc.dynamic

До сих пор все объекты в программах создавались объявлением: локальные переменные — при входе в блок, глобальные — при запуске программы. Их время жизни и размер известны компилятору заранее. Этого недостаточно в трёх случаях:

- **размер данных становится известен только во время работы** — например, количество чисел вводит пользователь;
- **объект должен пережить функцию, которая его создала**, — например, функция строит структуру данных и возвращает её вызывающему коду;
- **данных слишком много для стека**: размер стека ограничен, обычно несколькими мегабайтами (см. 1.3.6 «Как операционная система выделяет программе стек»).

Для этих случаев объект создают в динамической памяти. Контейнер `std::vector` из темы 3.2 решает все три задачи именно так — хранит элементы в динамической памяти и управляет ею сам.

> [!abstract] Динамическая память (dynamic memory)
> память, которую программа запрашивает и освобождает явно во время выполнения; время жизни объекта в ней не связано с блоком кода, а длится от создания выражением `new` до уничтожения выражением `delete`.

Стандарт C++ говорит не о «стеке» и «куче», а о длительности хранения объектов (см. выноску в [[lekciya-14#1.3.4 Стек вызовов и кадр стека (дополнения)|1.3.4 Стек вызовов и кадр стека]]). В курсе используются три её вида:

- **автоматическая** — локальные переменные и параметры: объект уничтожается при выходе из блока, память освобождается сама; на практике такие объекты располагаются в стеке;
- **статическая** — глобальные и `static`-переменные: существуют до завершения программы (тема 1.6);
- **динамическая** — объекты, созданные `new`: существуют, пока их явно не уничтожат. На практике память для них выделяется из кучи (heap).

Объект в динамической памяти не имеет имени. Программа знает о нём только по адресу, который вернуло выражение `new` и который хранится в указателе. Если этот адрес потерян, до объекта уже не добраться — и освободить его тоже.

### 3.3.6.2 Операторы `new` и `delete`

> [!quote] Документация и стандарт по теме
> - Выражение `new`: https://cppreference.com/cpp/language/new · стандарт: https://eel.is/c++draft/expr.new
> - Выражение `delete`: https://cppreference.com/cpp/language/delete · стандарт: https://eel.is/c++draft/expr.delete

> [!abstract] Выражение new (new-expression)
> выражение `new T` или `new T{инициализатор}`, которое выделяет динамическую память под объект типа `T`, создаёт в ней объект и возвращает указатель `T*` на него.

> [!abstract] Выражение delete (delete-expression)
> выражение `delete ptr`, которое уничтожает объект, созданный `new`, и освобождает занятую им память; `ptr` должен содержать адрес, полученный от `new`, или `nullptr`.

```cpp
int* a = new int;        // значение неопределённое (инициализация по умолчанию, 1.2.8.1); читать его до записи — UB
int* b = new int{};      // 0 — инициализация значением (value-initialization), см. 1.2.8.6
int* c = new int{42};    // 42

auto* student = new Student{"Иванов И. И.", 1, 8.5};  // структура из 1.1.2.6.2
student->average = 9.0;

delete a;
delete b;
delete c;
delete student;
```

Правила работы с `new` и `delete`:

1. Каждому `new` должен соответствовать ровно один `delete` для того же адреса.
2. После `delete ptr` указатель `ptr` не меняется: в нём остаётся прежний адрес, но объекта по этому адресу больше нет. Такой указатель — **висячий** (см. 3.3.6.5 «Ошибки работы с динамической памятью»).
3. `delete` для нулевого указателя (`int* p = nullptr; delete p;`) ничего не делает и ошибкой не является.
4. Если память выделить не удалось, `new` не возвращает `nullptr`, а выбрасывает исключение `std::bad_alloc` (тема 3.7). Проверять результат `new` на `nullptr` бессмысленно. Вариант, который при нехватке памяти возвращает `nullptr`, записывается как `new (std::nothrow) T` (заголовок `<new>`).

> [!example] Пример — Обычный `new` и `new (std::nothrow)` при нехватке памяти
> ```cpp
> #include <cstddef>
> #include <iostream>
> #include <new>     // std::nothrow, std::bad_alloc
>
> struct Sensor {
>     int id{};
>     Sensor()
>     // TODO: продолжение примера на фото не попало
> ```

На доске: `int* ptr2 = new int{…};`, `int* ptr2 = new int[10];`, `malloc`.
